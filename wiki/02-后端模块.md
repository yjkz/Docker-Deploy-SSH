# 02 — 后端模块(Rust)

后端共 12 个源文件(不含 main.rs),约 9,870 行。分层原则:**commands.rs 是部署主线的唯一编排层**;manage 系列模块(远程管理)自成一组,复用 commands.rs 公开的密码解析与 ssh.rs 的连接能力,不反向依赖;其余模块是可独立单测的纯逻辑或 I/O 封装。

全局约定:

- 命令统一返回 `Result<T, String>`,错误信息中文带上下文
- 非测试代码禁止对 Result/Option `unwrap()`/`expect()`(两处豁免:`Mutex::lock().unwrap()`——锁中毒直接 panic 的策略,manage_stats/manage_exec 使用;`config.rs` 的 `current_exe().expect`,签名固定为返回 PathBuf 所致)
- 所有跨前后端结构体 derive `Serialize`(+按需 `Deserialize`/`Clone`),字段 snake_case(serde 未设 rename_all,前端必须用 snake_case 读字段);**仅** manage 系列解析 docker 输出的内部结构体例外(上游 NDJSON 是 PascalCase,`#[serde(rename_all = "PascalCase")]` 仅 Deserialize,不外泄)
- 子进程一律参数数组不经 shell;SSH 远端命令一律经单引号转义(commands 层 `shell_single_quote`,manage 层 `shell_quote`,实现相同)
- 远程管理统一超时梯度:建连 15s / 常规 exec 60s / 镜像 pull 300s / 栈 up-down 120s

## manage_stats.rs(545 行)— docker stats 实时监控(C 阶段,2 命令)

事件流式监控:`manage-stats` 事件每轮推送 `{ server_id, stats: Vec<StatsRow>, error, stopped }`(payload 结构见 04)。

- **会话模型**:全局单会话。`StatsState`(Builder `.manage()` 注册)内部 `generation`(会话代号)+`running`;`manage_stats_start` 递增 generation 并 `tokio::spawn` 轮询循环,循环每轮(含等待间隔的每 200ms)检查自己代号是否仍最新,过期即退出——旧会话自清理、重复 start 无缝接管;`manage_stats_stop` 递增代号即可
- **连接模型**:一个会话只建一条 SSH 连接跨轮复用(`SshClient::exec` 每次各自开新通道,复用安全);传输层失败→发 error payload 后丢弃旧连接立即重连一次;**连续 3 轮(`MAX_CONNECT_FAILURES`)连接失败→发 `stopped:true` 并停止**
- **单轮失败分类**(`RoundOutcome`):`Success` / `PermDenied`(权限拒绝,立即停止) / `CommandFailed`(退出码非 0 或解析失败,连接仍可用,继续) / `TransportFailed`(通道打不开/执行超时/退出码 -1,按 `is_transport_error` 文案匹配判连,需重连)
- **旧版 Docker 降级**:`docker stats --no-stream --format json` 简写不可用(退出码非 0,或把 "json" 当模板文本原样输出)时降级 `'{{json .}}'` 模板(`JSON_SHORTHAND_OK` 进程级 AtomicBool,降级一次全局生效)
- 轮询间隔 clamp 1-60s,默认 2s;每轮套 `with_timeout` 防 hang

## manage_exec.rs(521 行)— 容器交互式终端(C 阶段,4 命令)

经 `ssh.rs` 的 `exec_interactive` 打开 PTY 执行 `docker exec -it <c> <shell>`,输出经 `manage-exec-output` 事件推送 `{ session_id, data, eof, error }`。

- **会话表**:`ExecState`(Builder `.manage()` 注册)内 `Mutex<HashMap<String, ExecSession>>`;`ExecSession { _client(保活 SSH 连接), write_tx, resize_tx, stop_tx }`(全部 mpsc 句柄,持锁时只 clone 绝不 await);session_id=时间戳+进程内计数器
- **shell 自动探测**(`probe_container_shell`):开终端前在同连接上跑非交互 `docker exec <c> sh -c <探测脚本>`——`command -v` 只验存在性,故对 bash/sh 追加 `bash -c true` **可执行性验证**(真机取证:docker exec 退出码 126=文件在但不可执行,127=不存在);bash 优先退回 sh;探测脚本不含单引号(有单测保证 shell_quote 无损);distroless(最外层 127)报「容器内未找到可用的 shell」
- **任务模型**:start 先注册会话再启动读任务(防"先清理后插入"竞态);写任务持 `channel.make_writer()` 从 mpsc 队列写 stdin;读任务 `tokio::select!` 并发处理输出/resize(`window_change`)/stop;会话结束时组装结束原因(用户停止不提示 / 写失败 / 远端退出码 127/126 有针对性提示+输出尾段 OCI 原文 / 通道关闭)随 eof 事件透出,并自移除会话
- **纯函数辅助**(有单测):`strip_ansi`(CSI/OSC/C0)、`last_output_line`(去 ANSI 取最后一个非空行,按字符边界截尾)

## 模块依赖关系

```
lib.rs ──▶ commands.rs ──┬─▶ config.rs(配置实体;无内部依赖)
                         ├─▶ docker.rs(本机 Docker;仅标准库+flate2/chrono/fs4)
                         ├─▶ ssh.rs(SSH/SFTP;依赖 config::ServerConfig)
                         ├─▶ crypto.rs(DPAPI;无内部依赖)
                         ├─▶ stack.rs(compose 解析;依赖 config::TransferMode/ServiceOverride)
                         └─▶ history.rs(部署历史;复用 config 的原子写与目录)
      └─▶ manage.rs ──────────▶ ssh.rs(exec_collect)+ commands::resolve_password(pub)
      └─▶ manage_stacks.rs ───▶ manage.rs(连接/执行助手)
      └─▶ manage_stats.rs ────▶ manage.rs + ssh.rs
      └─▶ manage_exec.rs ─────▶ manage.rs + ssh.rs(exec_interactive)

另:lib.rs 注册 tauri-plugin-dialog(文件浏览对话框,前端经 __TAURI__.dialog 调用,无自定义命令);
    .manage() 注册三个状态:DeployState / manage_stats::StatsState / manage_exec::ExecState
```

依赖方向纪律:**manage 系列不依赖 stack.rs/history.rs/docker.rs,commands.rs 也不依赖 manage 系列**——部署主线与远程管理完全正交,仅共享 config/ssh/crypto 的底层能力。

`stack.rs`、`docker.rs`、`crypto.rs`、`manage_exec.rs`(strip_ansi/last_output_line)的核心函数是纯函数或单参 I/O,**单测不依赖 Docker/网络**(`cargo test` 142 passed);真机行为测试标 `#[ignore]`(7 个),`cargo test -- --ignored` 单独跑。
