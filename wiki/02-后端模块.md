# 02 — 后端模块(Rust)

后端共 17 个源文件(不含 main.rs),约 22,300 行。分层原则:**commands.rs 是部署主线的唯一编排层**;manage 系列模块(远程管理)自成一组,复用 commands.rs 公开的密码/私钥口令解析与 ssh.rs 的连接能力,不反向依赖;通知(notify)、配置中心(config_io)、检查更新(update)是旁路功能模块,只依赖 config/crypto 底层,不触碰部署管线;**项目跨服务器迁移**(migrate_project,第六批)以项目为单位搬运镜像/compose/数据卷/归档,复用 commands 的连接与镜像搬运助手,并在成功后改绑项目配置(见该节);其余模块是可独立单测的纯逻辑或 I/O 封装。

全局约定:

- 命令统一返回 `Result<T, String>`,错误信息中文带上下文
- 非测试代码禁止对 Result/Option `unwrap()`/`expect()`(豁免:`Mutex::lock().unwrap()`——锁中毒直接 panic 的策略,manage_stats/manage_exec 使用;`config.rs` 的 `current_exe().expect`,签名固定为返回 PathBuf 所致)
- 所有跨前后端结构体 derive `Serialize`(+按需 `Deserialize`/`Clone`);**字段命名默认 snake_case**(serde 未设 rename_all);**例外**:升级新增的前端契约结构(notify.rs 全部、`ImportSummary`/`AppSettings`/`UpdateInfo`/`ReleaseBrief`/`StackEnv`、阶段六至八的批量部署/断点续传/清理分析系列)显式 `#[serde(rename_all = "camelCase")]`,完整清单见 04;仅 manage 系列解析 docker 输出的内部结构体用 PascalCase(`#[serde(rename_all = "PascalCase")]` 仅 Deserialize,不外泄)
- 子进程一律参数数组不经 shell;SSH 远端命令一律经单引号转义(commands 层 `shell_single_quote`,manage 层 `shell_quote`,实现相同)
- 远程管理统一超时梯度:建连 15s / 常规 exec 60s / 镜像 pull 300s / 栈 up-down 120s

  pub skip_unchanged: Option<bool>,    //   single/stack 通用,缺省 false

### 智能传输与一键回滚(阶段一)

- **智能传输**:判定=镜像 ID(内容寻址)。整栈:打包前建连查远端 ID 映射,本地侧 `list_images` 的 ID 同口径比对;未变化服务按 skip/force_archive 矩阵跳过或仅留档(全未变化时三步全跳);单镜像:仅非日期标签模式生效,跳过时保留对比阶段连接复用到上传步(不重连)
- **留档增强**:整栈成功收尾写发布目录 `manifest.json`(`ReleaseManifest { project, ts, compose_copy, images: Vec<ManifestImage { service, tag, file }>, }`;跳过未留档的服务 `file=null`)经 base64 远端解码写入(避免 JSON 引号转义),compose 副本 sftp 归档为 `docker-compose.yml`;`build_manifest_images` 纯函数有单测;**尽力而为**,失败仅告警(回滚命令优雅降级)
- **一键回滚**(4 命令,见 04 契约):`rollback_list_releases`(列表+manifest 降级)/ `rollback_list_tags`(历史标签倒序)/ `rollback_execute_stack`(逐包 load → 恢复 compose 副本 → up;**留档归属校验**防误回滚共用目录的其他项目)/ `rollback_execute_single`(校验标签存在 → docker tag → up);成功落 `mode="rollback"` 历史
- `DeployRecord.release_dir`(history.rs):整栈成功记录留档目录路径,serde default 兼容旧记录

### 断点续传 / 批量部署 / 清理分析(阶段六至八)

**部署断点(阶段六,checkpoint)**:单发部署管线每个步骤边界 `save_checkpoint` 落盘 `{step_next(失败步骤号,续传起点), ts, artifacts(该模式结构的产物 JSON)}`,键 `server_id|project_id|mode`(单镜像 5 步/整栈 6 步映射,整栈 mkdir 后复用发布目录);单镜像/整栈断点互为不同键并存。断点期本地 tar 由守卫保留(TempFileGuard keep),成功清理产物+删断点,取消保留断点;同一服务器+项目的新部署同键覆盖。`deploy_resume_start` 校验断点与服务器/项目仍存在后,构造与单发一致的请求走 `spawn_deploy_task`(resume=Some(ctx)),事件/历史/通知语义与正常部署完全一致;`deploy_resume_discard` 删断点 + 本地临时 tar + 尽力删远端产物(单镜像 `/tmp` tar、整栈 releases 半成品目录,失败仅日志)。管线幂等化:本地 tar 存在且大小匹配(不匹配重跑导出)、远端 tar 经 `sftp_stat_size` 断点续传、load 前远端 ID 比对跳过、compose up 天然幂等。

**批量部署(阶段七)**:⚠️ **生效的实现不在本模块**。实际生效的是**前端编排** ——
`ui/deploy.js` 的 `st.batch` 串行队列逐台调 `server_env_check` + 单发 `deploy`/`deploy_stack`
(await `deploy-done`),自己维护状态并渲染 `#deploy-batch-panel`。见 03/06 与 wiki 01 的注。

下面这套是阶段七**最初的后端编排实现,现已无任何前端调用点(死代码)**:
`deploy_batch` 命令 + `validate_batch_request`(同步校验:mode 合法/server_ids 去重非空/项目存在/
模式所需字段齐备)+ `run_batch_deploy` **逐台串行**执行与单发一致的管线(仅替换 server_id),
每台 emit `deploy-batch{state:"running"|"success"|"failed"|"skipped"}`,结束追加 `state:"batch-done"`
汇总;批量路径**不发** deploy-progress/deploy-done(`DeployEmitOpts::batch`)、deploy-log 每行加
`[服务器名] ` 前缀、**不落断点**。

删除与否待定:保留它会持续误导排查方向(同名命令 + 同族事件),但它也是唯一「后端编排」的

**清理分析(阶段八;第三批重构,`cleanup_preview` / `cleanup_execute`)**:预览只读,各节独立查询互不阻断。**无标签镜像**改用 `docker images --no-trunc --format '{{json .}}'` 全量拉取后客户端过滤 `Repository/Tag == "<none>"` —— 旧实现用 `docker images -f dangling=true`,该过滤在 BuildKit / containerd image store 下常返回空(表现为「有 `<none>` 镜像却识别不到」);容器引用集合(`docker ps -a --no-trunc` + `docker inspect --format '{{.Image}}'`)标记在用项。停止容器、未使用卷、build cache 三节口径不变。**容错**:`parse_cleanup_ndjson` 跳过非 JSON 行收进 `warnings`(旧实现任何一行非 JSON 即整节解析失败、列表恒空 —— 服务端一句 `WARNING: No swap limit support` 就能触发);单条命令的退出码与输出摘要进 `diagnostics` 供前端展示。**分项目扫描**(`scan_cleanup_projects`):`find` 扫 compose(深度 ≤4,排除 `releases/`、`.git`)→ 目录去重 → `du -sh` 取占用 → 逐目录 `cat` compose 提取 `image` 仓库名 → 按仓库名归属 releases 归档与日期标签镜像(`YYYYmmdd-HHMMSS`,由 `is_date_tag` 纯函数判定)。**执行**:按前端回传的**显式目标列表**逐条删除(`rmi` ID / `rm` ID / `volume rm` / `rm -rf` 归档),取代原 `prune -f` —— prune 的删除范围由 docker 自行判定,可能与勾选项不一致(`volume prune` 连未列出的未使用卷一起删);逐节 catch,单节失败(含传输层错误)不中断后续;300s/节超时,流式输出 `server-log`。

## manage_stats.rs(545 行)— docker stats 实时监控(C 阶段,2 命令)

## 模块依赖关系

```
lib.rs ──▶ commands.rs ──┬─▶ config.rs(配置实体;无内部依赖)
                         ├─▶ docker.rs(本机 Docker;仅标准库+flate2/chrono/fs4)
                         ├─▶ ssh.rs(SSH/SFTP;依赖 config::ServerConfig)
                         ├─▶ crypto.rs(DPAPI;无内部依赖)
                         ├─▶ stack.rs(compose 解析;依赖 config::TransferMode/ServiceOverride)
                         ├─▶ history.rs(部署历史;复用 config 的原子写与目录)
                         └─▶ notify.rs(通知中心 fire;依赖 config + crypto)
      └─▶ notify.rs ───────────▶ config.rs + crypto.rs(+ tauri-plugin-notification / lettre)
      └─▶ config_io.rs ────────▶ config.rs + crypto.rs(+ argon2 / aes-gcm)
      └─▶ update.rs ───────────▶ (无内部依赖;reqwest)
      └─▶ manage.rs ──────────▶ ssh.rs(exec_collect)+ commands::resolve_password /
      │                          resolve_key_passphrase / persist_host_key_if_needed
      └─▶ manage_stacks.rs ───▶ manage.rs(连接/执行助手)
      └─▶ manage_stats.rs ────▶ manage.rs + ssh.rs
      └─▶ manage_exec.rs ─────▶ manage.rs + ssh.rs(exec_interactive)
      └─▶ migrate_project.rs ─▶ commands.rs(连接/镜像搬运/命令拼装助手)+ stack.rs(卷解析)

另:lib.rs 注册 tauri-plugin-dialog(文件/保存对话框)与 tauri-plugin-notification(桌面通知);
    .manage() 注册五个状态:DeployState / manage_stats::StatsState / manage_exec::ExecState /
              manage_logs::LogsState / commands::MigrateState;
    桌面构建附加 setup_desktop:系统托盘 + 主窗口关闭拦截(现读 settings.json)
```

依赖方向纪律:**manage 系列不依赖 stack.rs/history.rs/docker.rs,commands.rs 不依赖 manage 系列**(仅经由 manage 复用的 pub(crate) 助手反向提供);**notify/config_io/update 不触碰部署管线**,只消费 config/crypto 底层——部署主线、远程管理、旁路功能三组正交,仅共享 config/ssh/crypto 的底层能力。

`stack.rs`、`docker.rs`、`crypto.rs`、`manage_exec.rs`(strip_ansi/last_output_line)、`notify.rs`(校验/分类/端口兜底纯函数)、`config_io.rs`(信封 seal/open)、`update.rs`(版本比较/Location 解析)、`config.rs`(断点裁剪 trim_checkpoints)、`migrate_project.rs`(卷名推导/目标目录解析/体积格式化/事件 camelCase 契约)、`commands.rs`(same_image_id/manifest 组装/通知文案/路径与命令拼装/批量请求校验 validate_batch_request/镜像 ID 命令与解析)的核心逻辑是纯函数或单参 I/O,**单测不依赖 Docker/网络**(`cargo test` 269 passed);真机行为测试标 `#[ignore]`(13 个,含阶段九 `exec_streaming` 自然结束+取消、阶段十 `sftp_download` 全字节 roundtrip、第六批卷导出导入 roundtrip),`cargo test -- --ignored` 单独跑。
