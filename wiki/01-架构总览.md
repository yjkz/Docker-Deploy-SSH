通信规则:

1. **前端 → 后端**:`AppBus.invoke(cmd, args)` → `window.__TAURI__.core.invoke`。参数名 JS 侧 camelCase(Tauri 2 自动映射到 Rust snake_case 形参);**对象内部字段默认 snake_case**(serde 未设 rename_all)——升级新增的 notify/config_io/settings/update/rollback 列表/`.env`/批量部署/断点续传/清理分析契约结构为 camelCase(例外清单见 04)。
2. **后端 → 前端**:12 个事件(`deploy-progress` / `deploy-log` / `deploy-done` / `deploy-batch`⚠️死代码 / `server-log` / `manage-stats` / `manage-exec-output` / `manage-logs` / `migrate-log` / `migrate-done` / `migrate-project-log` / `migrate-project-done`),载荷字段 snake_case(deploy-batch/manage-logs/migrate 系列为 camelCase);回滚执行期复用 deploy-log/deploy-done,批量执行期不发这两个事件;迁移进度/结果经 migrate-log/migrate-done。
3. **长任务模型**:①`deploy` / `deploy_stack` / `rollback_execute_*` / `deploy_resume_start` 同步立即返回 `Ok(())`,实际工作在 `tauri::async_runtime::spawn` 中执行,进度/结果只经事件,`DeployState(AtomicBool cancelled)` 提供协作式取消;②**批量部署由前端编排**(见 03/06:deploy.js 的 `st.batch` 串行队列,逐台复用单发 `deploy`/`deploy_stack`);后端 `deploy_batch` 命令是阶段七的**未接入遗留实现**(无任何前端调用点,详见 02 末注);③`manage_stats_start` spawn 轮询循环,数据经 `manage-stats` 事件流式推送,全局单会话(generation 代号)自动接管/停止;④`manage_exec_start` 启动 PTY 读写后台任务,输出经 `manage-exec-output` 事件推送,会话表随 eof 自清理。
4. **Docker 全部走 CLI 子进程**(参数数组,不经 shell;本机检测/导出);**服务器 Docker 走 SSH 远程命令**(部署管线经 `shell_single_quote`,远程管理经 manage 层 `shell_quote`,实现相同——见 07 安全)。
5. **旁路功能不阻塞主线**:通知中心(`notify::fire` 异步分发,失败仅日志)、检查更新、webhook 均不影响部署结果与 history。

## 三条主线数据流

**① 部署 — 单镜像**(`deploy` 命令;进度步骤号与前端校准仪 5 节点 TAG/PACK/UPLOAD/SYNC/APPLY 一一对应):

```
前端选镜像/服务器/项目(+传输选项) → deploy(req) ──spawn──▶ ①打标签(日期 tag,重试 5×1s)
  ②导出压缩(智能传输判定:非日期标签且 skip_unchanged 时远端 --no-trunc ID == 本地 ID
    → 跳过导出/上传/装载;否则 save+gzip,本地+远端磁盘 ×1.5 预检)
  ③上传镜像到服务器(/tmp;失败同路径断点续传重试一次 + 文件映射)
  ④同步项目文件(prepare_single_compose 上传 compose(+.env/override)+ sync_files + pre 钩子)
  ⑤服务器部署(docker load → 原标签同步(日期 tag→原 tag)→ compose up -d → 健康检查 → post 钩子
    → 删远端/本地 tar);每步边界落部署断点(resume-deploy.json,失败/取消可从断点续传);
    全程 emit deploy-progress(1..5)/deploy-log;结束 emit deploy-done → 写部署历史
    (deployments.json)+ webhook + 通知中心 fire
```

**② 部署 — 整栈**(`deploy_stack` 命令):

```
导入 compose(副本入 config/stacks)→ parse_compose(三级匹配+分类)→ 前端分类表确认
→ deploy_stack(req) ──spawn──▶ ①分类确认 ②智能传输判定(skip_unchanged×force_archive 矩阵:
  未变化服务跳过打包/仅留档)→ 并行打包(并发 3,本地+远端磁盘预检)
③上传到 releases/<时间戳>/(断点续传;含 compose 副本+override→远端 + 文件映射)
→ pre 钩子 → ④逐包 docker load(留档的未变化镜像仅归档不装载)⑤compose pull(私有仓库提示)
⑥compose up -d → 健康检查(ps --all+ExitCode)→ post 钩子 → releases 只留最新 5 份
→ 收尾:发布目录写 manifest.json(逐服务镜像条目+compose 副本名,尽力而为)+ DeployRecord
  落 release_dir → 部署历史 + webhook + 通知中心 fire(单镜像/整栈管线每步边界同样落部署断点)
```

**②' 批量部署**(阶段七;**前端编排**,`deploy.js` 的 `st.batch` 串行队列):

```
04 页选模式/项目 + 多选服务器 → 前端队列逐台:server_env_check 预检 → 复用单发
  deploy / deploy_stack(await deploy-done);单台状态由前端写入 st.batch.results 并渲染
  #deploy-batch-panel(等待/部署中/成功/失败/已跳过 + 计数行);
  每台独立写部署历史(可逐台回滚)+ 通知;批量路径不落断点;
  「停止批量」= 只停队列、当前台跑完即止,余台标 skipped(批量不落断点,半途取消会
  留下无法续传的半成品);要立即中止当前台用「取消部署」(该台记 skipped 并同样停掉余台)
```

> 注:后端 `commands::deploy_batch`(`BatchDeployRequest` / `run_batch_deploy` / `deploy-batch`
> 事件 / `BATCH_STATE_*`)是阶段七最初的**后端编排实现**,后来改为前端编排但未删除,
> 目前**没有任何前端调用点**。改批量行为请看 `ui/deploy.js`,不要动 `run_batch_deploy`。

**③ 远程管理**(manage 系列命令,v4.5.0 起三阶段 + v5.1 补遗):

```
05 远程管理页选服务器 ──▶ 短命令:每命令独立建连(15s)→ SSH exec docker 命令(60/120/300s)
                         → 解析 NDJSON→snake_case → 返回值直返(无事件)
                         ├─ 容器/镜像/卷/网络(manage.rs 20 命令)
                         └─ Compose 栈:find 扫描 remote_dir 深度≤2 → up/down/ps/logs(4 命令)
                            + 同目录 .env 查看/编辑(base64 传输,2 命令)
        长任务:实时监控 manage_stats_start ──spawn 轮询 docker stats──▶ manage-stats 事件流
               (单连接跨轮复用;generation 单会话;连续 3 轮连接失败/权限拒绝自动停)
               交互终端 manage_exec_start ──PTY──▶ manage-exec-output 事件流
               (shell 自动探测存在性+可执行性;eof 自清理;resize 随窗口自适应上报)
```

**④ 清理分析 + 项目源更新**(03 页入口,阶段八 + 第三批):

```
03 页「清理优化」→ cleanup_preview({ serverId, scanRoot? }) 只读扫描
  ├─ 无标签镜像:docker images 全量 + 客户端过滤 <none>(不用 -f dangling=true;
  │  BuildKit/containerd store 下该过滤常返回空)+ 容器引用集合标记在用
  ├─ 停止容器 / 未使用卷 / build cache
  └─ 分项目:find 扫 compose(深度≤4,排除 releases/.git)→ du -sh → cat compose
     取 image 仓库名 → 归属 releases 归档与日期标签镜像(YYYYmmdd-HHMMSS)
→ 模态勾选(在用项禁选)→ cleanup_execute 按显式目标列表逐条删除
  (rmi/rm/volume rm/rm -rf;不用 prune -f——其删除范围由 docker 自判,与勾选不符)

启动/手动 → check_project_sources(比对导入源 compose+.env+override 的 sha256)
  → changed 的走 update_project_from_source(备份 .bak → 重拷重解析 → 保留 service_overrides)
```

**⑤ 项目跨服务器迁移**(`migrate_project.rs`,第六批,2 命令):

```
04 页「迁移项目…」→ migrate_project_preview(只读):连源读 <源目录>/docker-compose.yml
  (以源实际部署为准)→ 解析镜像/卷/近 N 归档 → 计划(含 warnings/errors)前端确认
→ migrate_project_start ──spawn──▶ ②源 stop → ③逐卷 tar 导出 → ④源 start(无条件恢复)
  → ⑤镜像/卷包/归档经本机中转(save_gzip_remote → sftp_upload;目标同 ID 跳过)
  → ⑥目标 load + volume create/导入(按目标侧卷名)→ ⑦compose 三件套与归档落盘
  → ⑧目标 up -d → ⑨清两端临时产物 → ⑩改绑 default_server_id + 写 mode="migrate" 历史;
  进度 emit migrate-project-log,结束 emit migrate-project-done{success,message,warnings}
```

**项目目录检测/创建**(第六批,03 页项目表单):`check_remote_dir({serverId, dir})`(只读 `test -d`)→ 不存在则 `create_remote_dir_at`(`mkdir -p`)→ 前端自动重新检测。两个命令都接受任意绝对路径(项目级目录可与服务器级不同),与服务器级的 `create_remote_dir` 分开。

**配套旁路**:部署/回滚收尾 → `notify::fire`(桌面+邮件,按订阅);04 页断点续传 → `deploy_resume_status/start/discard`(走与正常部署完全一致的 spawn 路径);03 页清理分析 → `cleanup_preview`(只读)/`cleanup_execute`(按显式目标定向删除,输出经 server-log);03 页项目源更新 → `check_project_sources`/`update_project_from_source`;**06 页回滚中心 → `rollback_scan_projects`/`rollback_project_detail`/`rollback_execute_stack_at`(按服务器真实目录,不依赖软件内 projectId)**;05 页日志实时跟随 → `manage_log_stream_start/stop`(manage-logs 事件流,ssh.rs `exec_streaming` 可取消流式);05 页镜像迁移 → `migrate_images`/`migrate_status`(migrate-log/migrate-done 事件,ssh.rs `sftp_download` + `raw_exec_channel`);03 页配置中心 → `config_export_file`/`config_import_file`/`config_wipe`;dock 设置 → `app_settings_get/set` + `update_check`/`update_download`/`update_install`。
