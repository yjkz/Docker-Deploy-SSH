# 01 — 架构总览

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | **Tauri 2**(tauri 2.11.3) | WebView2 承载前端;`withGlobalTauri: true` 暴露 `window.__TAURI__`;窗口 1280×850(min 1200×800) |
| 后端语言 | **Rust**(stable,edition 2021) | 全部业务逻辑在 Rust,前端只做呈现 |
| SSH/SFTP | russh 0.46 + russh-sftp 2.4 | 纯 Rust 实现;主机密钥无条件接受(有意取舍,见 07);交互终端经 `request_pty` 伪终端 |
| 压缩 | flate2(gzip 流式) | `docker save` stdout → GzEncoder → 文件,不依赖系统 gzip |
| YAML | serde_yaml 0.9(含 `apply_merge` 处理合并键) | compose 解析 |
| 密码加密 | windows-dpapi(CurrentUser)+ base64 | 仅 `cfg(windows)` 依赖 |
| 磁盘空间 | fs4 0.12 | host_check 磁盘项 + 导出前 ×1.5 预检 |
| 日志 | tauri-plugin-log(Info) | 文件 `logs/app.log` 全构建启用;Stdout 仅 debug(release 是 GUI 子系统进程,写 stdout 会 panic) |
| 前端 | 原生 HTML/CSS/JS | **无框架、无打包器、无 npm 运行时依赖**;`ui/` 目录即 frontendDist;字体自捆绑(Space Grotesk / JetBrains Mono / Noto Sans SC,woff2 + OFL 许可) |

通信规则:

1. **前端 → 后端**:`AppBus.invoke(cmd, args)` → `window.__TAURI__.core.invoke`。参数名 JS 侧 camelCase(Tauri 2 自动映射到 Rust snake_case 形参);**对象内部字段一律 snake_case**(serde 未设 rename_all)。
2. **后端 → 前端**:6 个事件(`deploy-progress` / `deploy-log` / `deploy-done` / `server-log` / `manage-stats` / `manage-exec-output`),载荷字段 snake_case。
3. **长任务模型**:①`deploy` / `deploy_stack` 同步立即返回 `Ok(())`,实际工作在 `tauri::async_runtime::spawn` 中执行,进度/结果只经事件,`DeployState(AtomicBool cancelled)` 提供协作式取消;②`manage_stats_start` spawn 轮询循环,数据经 `manage-stats` 事件流式推送,全局单会话(generation 代号)自动接管/停止;③`manage_exec_start` 启动 PTY 读写后台任务,输出经 `manage-exec-output` 事件推送,会话表随 eof 自清理。
4. **Docker 全部走 CLI 子进程**(参数数组,不经 shell;本机检测/导出);**服务器 Docker 走 SSH 远程命令**(部署管线经 `shell_single_quote`,远程管理经 manage 层 `shell_quote`,实现相同——见 07 安全)。

## 三条主线数据流

**① 部署 — 单镜像**(`deploy` 命令):

```
前端选镜像/服务器/项目 → deploy(req) ──spawn──▶ ①tag ②save+gzip(本地+远端磁盘×1.5预检)
→ ③SFTP 上传 /tmp(失败同路径断点续传重试一次)+ 文件映射 + compose 上传(prepare_single_compose)
→ pre 钩子 → ④docker load → 原标签同步(docker tag 日期tag→原tag)→ ⑤compose up -d
→ 健康检查 → post 钩子 → 删远端/本地 tar;全程 emit deploy-progress(1..5)/deploy-log
;结束 emit deploy-done → 写部署历史(deployments.json)+ webhook 通知
```

**② 部署 — 整栈**(`deploy_stack` 命令):

```
导入 compose(副本入 config/stacks)→ parse_compose(三级匹配+分类)→ 前端分类表确认
→ deploy_stack(req) ──spawn──▶ ①分类确认 ②并行打包(并发 3,本地+远端磁盘预检)
③上传到 releases/<时间戳>/(断点续传;含 compose 副本+override→远端 + 文件映射)
→ pre 钩子 → ④逐包 docker load ⑤compose pull(私有仓库提示)⑥compose up -d
→ 健康检查(ps --all+ExitCode)→ post 钩子 → releases 只留最新 5 份
→ 部署历史 + webhook 通知
```

**③ 远程管理**(manage 系列命令,v4.5.0 起三阶段):

```
05 远程管理页选服务器 ──▶ 短命令:每命令独立建连(15s)→ SSH exec docker 命令(60/120/300s)
                         → 解析 NDJSON→snake_case → 返回值直返(无事件)
                         ├─ 容器/镜像/卷/网络(manage.rs 20 命令)
                         └─ Compose 栈:find 扫描 remote_dir 深度≤2 → up/down/ps/logs(4 命令)
        长任务:实时监控 manage_stats_start ──spawn 轮询 docker stats──▶ manage-stats 事件流
               (单连接跨轮复用;generation 单会话;连续 3 轮连接失败/权限拒绝自动停)
               交互终端 manage_exec_start ──PTY──▶ manage-exec-output 事件流
               (shell 自动探测存在性+可执行性;eof 自清理)
```

详细语义见 [06-部署流程与回滚.md](06-部署流程与回滚.md)(部署)与 [04-契约参考.md](04-契约参考.md)(命令级)。
