# 01 — 架构总览

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | **Tauri 2**(tauri 2.11.3) | WebView2 承载前端;`withGlobalTauri: true` 暴露 `window.__TAURI__` |
| 后端语言 | **Rust**(stable,edition 2021) | 全部业务逻辑在 Rust,前端只做呈现 |
| SSH/SFTP | russh 0.46 + russh-sftp 2.4 | 纯 Rust 实现;主机密钥无条件接受(有意取舍,见 07) |
| 压缩 | flate2(gzip 流式) | `docker save` stdout → GzEncoder → 文件,不依赖系统 gzip |
| YAML | serde_yaml 0.9(含 `apply_merge` 处理合并键) | compose 解析 |
| 密码加密 | windows-dpapi(CurrentUser)+ base64 | 仅 `cfg(windows)` 依赖 |
| 磁盘空间 | fs4 0.12 | host_check 磁盘项 + 导出前 ×1.5 预检 |
| 日志 | tauri-plugin-log(Info) | 文件 `logs/app.log` 全构建启用;Stdout 仅 debug(release 是 GUI 子系统进程,写 stdout 会 panic) |
| 前端 | 原生 HTML/CSS/JS | **无框架、无打包器、无 npm 运行时依赖**;`ui/` 目录即 frontendDist |

```
│  ┌──────────────────────┐   invoke    ┌─────────────────────────────────────┐ │

│                                        │   ├─ ssh.rs     SSH/SFTP 客户端    │ │
│                                        │   ├─ crypto.rs  DPAPI 加解密       │ │

                            (docker save/tag/  (docker load/     config/*.json
                             inspect/images)    compose pull/up)  logs/app.log
                                               SFTP 上传
```

通信规则:

1. **前端 → 后端**:`AppBus.invoke(cmd, args)` → `window.__TAURI__.core.invoke`。参数名 JS 侧 camelCase(Tauri 2 自动映射到 Rust snake_case);**对象内部字段一律 snake_case**(serde 未设 rename_all)。
2. **后端 → 前端**:4 个事件(`deploy-progress` / `deploy-log` / `deploy-done` / `server-log`),载荷字段 snake_case。
3. **长任务模型**:`deploy` / `deploy_stack` 同步立即返回 `Ok(())`,实际工作在 `tauri::async_runtime::spawn` 中执行,进度/结果只经事件;`DeployState(AtomicBool cancelled)` 提供协作式取消。
4. **Docker 全部走 CLI 子进程**(参数数组,不经 shell);服务器操作全部走 SSH 单引号转义命令(见 07 安全)。

## 运行期文件布局(安装目录,便携式)

```
<安装目录>/
├── app.exe / DockerDeploy SSH.exe
├── config/
│   ├── servers.json            # 服务器列表(密码字段为 DPAPI base64 密文)
│   ├── projects.json           # 部署项目列表(含 service_overrides / 钩子 / 健康检查 / webhook)
│   ├── deployments.json        # 部署历史(上限 200 条,最新在末尾)
│   └── stacks/<uuid>/          # 导入的 compose 副本(docker-compose.yml + .env [+ override] + origin.json)
└── logs/app.log                # 运行日志(Info 级,自动轮转)
```

`config_dir()` 优先读环境变量 `DD_CONFIG_DIR`(测试注入用,语义=应用目录,内部再拼 `config/`),否则取 `current_exe()` 父目录。

## 两条主线数据流

**单镜像部署**(`deploy` 命令):

```
前端选镜像/服务器/项目 → deploy(req) ──spawn──▶ ①tag ②save+gzip(本地+远端磁盘×1.5预检)
→ ③SFTP 上传 /tmp(失败同路径断点续传重试一次)+ 文件映射 → pre 钩子 → ④docker load
→ 原标签同步(docker tag 日期tag→原tag)→ ⑤compose up -d → 健康检查 → post 钩子
→ 删远端/本地 tar;全程 emit deploy-progress(1..5)/deploy-log;结束 emit deploy-done
→ 写部署历史(deployments.json)+ webhook 通知
```

**整栈部署**(`deploy_stack` 命令):

```
导入 compose(副本入 config/stacks)→ parse_compose(三级匹配+分类)→ 前端分类表确认
→ deploy_stack(req) ──spawn──▶ ①分类确认 ②并行打包(并发 3,本地+远端磁盘预检)
③上传到 releases/<时间戳>/(断点续传;含 compose 副本+override→远端 + 文件映射)
→ pre 钩子 → ④逐包 docker load ⑤compose pull(私有仓库提示)⑥compose up -d
→ 健康检查(ps --all+ExitCode)→ post 钩子 → releases 只留最新 5 份
→ 部署历史 + webhook 通知
```

详细语义见 [06-部署流程与回滚.md](06-部署流程与回滚.md)。
