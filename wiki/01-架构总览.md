# 01 — 架构总览

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | **Tauri 2**(tauri 2.11.5) | WebView2 承载前端;`withGlobalTauri: true` 暴露 `window.__TAURI__`;窗口 1280×850(min 1200×800);桌面端内置 tray API 系统托盘(阶段四) |
| 后端语言 | **Rust**(stable,edition 2021) | 全部业务逻辑在 Rust,前端只做呈现 |
| SSH/SFTP | russh 0.46 + russh-sftp 2.4 | 纯 Rust 实现;主机密钥 **TOFU 校验**(阶段三,见 07);交互终端经 `request_pty` 伪终端 |
| 压缩 | flate2(gzip 流式) | `docker save` stdout → GzEncoder → 文件,不依赖系统 gzip |
| YAML | serde_yaml 0.9(含 `apply_merge` 处理合并键) | compose 解析 |
| 密码加密 | windows-dpapi(CurrentUser)+ base64 | 仅 `cfg(windows)` 依赖;SSH 密码/私钥口令/SMTP 密码统一 DPAPI |
| 导出加密 | argon2 0.5 + aes-gcm 0.10 | 配置导出文件:Argon2id 派生密钥 + AES-256-GCM 认证加密(阶段三,见 07) |
| 邮件 | lettre 0.11(smtp-transport + rustls-tls) | 通知中心 SMTP 邮件(ssl/starttls/none 三模式);tauri-plugin-notification 桌面通知(阶段二) |
| HTTP 客户端 | reqwest 0.12(rustls-tls + socks) | 检查更新(主路径 releases/latest 页 302 重定向解析 tag,回退 api.github.com);支持 http/socks5 自定义代理(阶段四) |
| 磁盘空间 | fs4 0.12 | host_check 磁盘项 + 导出前 ×1.5 预检 |
| 日志 | tauri-plugin-log(Info) | 文件 `logs/app.log` 全构建启用;Stdout 仅 debug(release 是 GUI 子系统进程,写 stdout 会 panic) |
| 前端 | 原生 HTML/CSS/JS | **无框架、无打包器、无 npm 运行时依赖**;`ui/` 目录即 frontendDist;字体自捆绑(Space Grotesk / JetBrains Mono / Noto Sans SC,woff2 + OFL 许可) |

通信规则:

1. **前端 → 后端**:`AppBus.invoke(cmd, args)` → `window.__TAURI__.core.invoke`。参数名 JS 侧 camelCase(Tauri 2 自动映射到 Rust snake_case 形参);**对象内部字段默认 snake_case**(serde 未设 rename_all)——升级新增的 notify/config_io/settings/update/rollback 列表/`.env`/批量部署/断点续传/清理分析契约结构为 camelCase(例外清单见 04)。
2. **后端 → 前端**:9 个事件(`deploy-progress` / `deploy-log` / `deploy-done` / `deploy-batch` / `server-log` / `manage-stats` / `manage-exec-output` / `manage-logs` / `migrate-log`+`migrate-done`),载荷字段 snake_case(deploy-batch/manage-logs/migrate 系列为 camelCase);回滚执行期复用 deploy-log/deploy-done,批量执行期不发这两个事件;迁移进度/结果经 migrate-log/migrate-done。
3. **长任务模型**:①`deploy` / `deploy_stack` / `rollback_execute_*` / `deploy_resume_start` 同步立即返回 `Ok(())`,实际工作在 `tauri::async_runtime::spawn` 中执行,进度/结果只经事件,`DeployState(AtomicBool cancelled)` 提供协作式取消;②`deploy_batch` 同样立即返回,后台任务逐台串行执行与单发一致的管线,单台状态经 `deploy-batch` 事件推送;③`manage_stats_start` spawn 轮询循环,数据经 `manage-stats` 事件流式推送,全局单会话(generation 代号)自动接管/停止;④`manage_exec_start` 启动 PTY 读写后台任务,输出经 `manage-exec-output` 事件推送,会话表随 eof 自清理。
4. **Docker 全部走 CLI 子进程**(参数数组,不经 shell;本机检测/导出);**服务器 Docker 走 SSH 远程命令**(部署管线经 `shell_single_quote`,远程管理经 manage 层 `shell_quote`,实现相同——见 07 安全)。
5. **旁路功能不阻塞主线**:通知中心(`notify::fire` 异步分发,失败仅日志)、检查更新、webhook 均不影响部署结果与 history。

## 运行期文件布局(安装目录,便携式)

```

├── app.exe / DockerDeploy SSH.exe
├── config/
│   ├── servers.json            # 服务器列表(密码/私钥口令为 DPAPI base64 密文 + TOFU 指纹)
│   ├── projects.json           # 部署项目列表(含 service_overrides / 钩子 / 健康检查 / webhook)
│   ├── notify.json             # 通知中心配置(SMTP 密码 DPAPI 密文;损坏时防写回保护)
│   ├── settings.json           # 应用设置:关闭到托盘 / 更新代理(camelCase)
│   ├── deployments.json        # 部署历史(上限 200 条,最新在末尾;含 rollback 记录)
│   ├── resume-deploy.json      # 部署断点表(键=服务器|项目|模式,上限 10 条裁最旧;损坏按空表自愈)
│   └── stacks/<uuid>/          # 导入的 compose 副本(docker-compose.yml + .env [+ override] + origin.json)
└── logs/app.log                # 运行日志(Info 级,自动轮转)
```

`config_dir()` 优先读环境变量 `DD_CONFIG_DIR`(测试注入用,语义=应用目录,内部再拼 `config/`),否则取 `current_exe()` 父目录。所有 json 均原子写(`.tmp` → rename)。跨机器迁移推荐用 03 页「配置中心」导出/导入(口令加密,密码经重加密可继续使用);直接拷贝 config/ 目录则 DPAPI 密文不可解,密码需重录。

## 三条主线数据流

**① 部署 — 单镜像**(`deploy` 命令):

```
前端选镜像/服务器/项目(+传输选项) → deploy(req) ──spawn──▶ ①tag ②智能传输判定(非日期标签
  且 skip_unchanged:远端 --no-trunc ID == 本地 ID → 跳过导出/上传/装载)→ save+gzip(本地+远端
  磁盘×1.5预检)→ ③SFTP 上传 /tmp(失败同路径断点续传重试一次)+ 文件映射 + compose 上传
  (prepare_single_compose)→ pre 钩子 → ④docker load → 原标签同步(docker tag 日期tag→原tag)
  → ⑤compose up -d → 健康检查 → post 钩子 → 删远端/本地 tar;每步边界落部署断点
  (resume-deploy.json,失败/取消可从断点续传);全程 emit deploy-progress(1..5)/
  deploy-log;结束 emit deploy-done → 写部署历史(deployments.json)+ webhook + 通知中心 fire
```

**② 部署 — 整栈**(`deploy_stack` 命令):

```
导入 compose(副本入 config/stacks)→ parse_compose(三级匹配+分类)→ 前端分类表确认
→ deploy_stack(req) ──spawn──▶ ①分类确认 ②智能传输判定(skip_unchanged×force_archive 矩阵:
  未变化服务跳过打包/仅留档)→ 并行打包(并发 3,本地+远端磁盘预检)
③上传到 releases/<时间戳>/(断点续传;含 compose 副本+override→远端 + 文件映射)
→ pre 钩子 → ④逐包 docker load(留档的未变化镜像仅归档不装载)⑤compose pull(私有仓库提示)
⑥compose up -d → 健康检查(ps --all+ExitCode)→ post 钩子 → releases 只留最新 5 份
→ 收尾:发布目录写 manifest.json(逐服务镜像条目+compose 副本名,尽力而为)+ DeployRecord
  落 release_dir → 部署历史 + webhook + 通知中心 fire(单镜像/整栈管线每步边界同样落部署断点)
```

**②' 批量部署**(`deploy_batch` 命令,阶段七;前端多选服务器,后端后台任务编排):

```
04 页选模式/项目/多台服务器 → deploy_batch(req) ──spawn──▶ 逐台串行执行与单发完全一致的
  管线(仅替换 server_id):每台开始/成功/失败/跳过 emit deploy-batch(camelCase);
  deploy-log 每行加 [服务器名] 前缀;批量路径不发 deploy-progress/deploy-done、不落断点;
  每台独立写部署历史(可逐台回滚)+ 通知;取消 = 当前台中止 + 余台 skipped;结束发
  state="batch-done" 汇总条目(「N 成功 / M 失败 / K 跳过」)
```

**③ 远程管理**(manage 系列命令,v4.5.0 起三阶段 + v5.1 补遗):

```
05 远程管理页选服务器 ──▶ 短命令:每命令独立建连(15s)→ SSH exec docker 命令(60/120/300s)
                         → 解析 NDJSON→snake_case → 返回值直返(无事件)
                         ├─ 容器/镜像/卷/网络(manage.rs 20 命令)
                         └─ Compose 栈:find 扫描 remote_dir 深度≤2 → up/down/ps/logs(4 命令)
                            + 同目录 .env 查看/编辑(base64 传输,2 命令)
        长任务:实时监控 manage_stats_start ──spawn 轮询 docker stats──▶ manage-stats 事件流
               (单连接跨轮复用;generation 单会话;连续 3 轮连接失败/权限拒绝自动停)
               交互终端 manage_exec_start ──PTY──▶ manage-exec-output 事件流
               (shell 自动探测存在性+可执行性;eof 自清理;resize 随窗口自适应上报)
```

**④ 清理分析 + 项目源更新**(03 页入口,阶段八 + 第三批):

```
03 页「清理优化」→ cleanup_preview({ serverId, scanRoot? }) 只读扫描
  ├─ 无标签镜像:docker images 全量 + 客户端过滤 <none>(不用 -f dangling=true;
  │  BuildKit/containerd store 下该过滤常返回空)+ 容器引用集合标记在用
  ├─ 停止容器 / 未使用卷 / build cache
  └─ 分项目:find 扫 compose(深度≤4,排除 releases/.git)→ du -sh → cat compose
     取 image 仓库名 → 归属 releases 归档与日期标签镜像(YYYYmmdd-HHMMSS)
→ 模态勾选(在用项禁选)→ cleanup_execute 按显式目标列表逐条删除
  (rmi/rm/volume rm/rm -rf;不用 prune -f——其删除范围由 docker 自判,与勾选不符)

启动/手动 → check_project_sources(比对导入源 compose+.env+override 的 sha256)
  → changed 的走 update_project_from_source(备份 .bak → 重拷重解析 → 保留 service_overrides)
```

**配套旁路**:部署/回滚收尾 → `notify::fire`(桌面+邮件,按订阅);04 页断点续传 → `deploy_resume_status/start/discard`(走与正常部署完全一致的 spawn 路径);03 页清理分析 → `cleanup_preview`(只读)/`cleanup_execute`(按显式目标定向删除,输出经 server-log);03 页项目源更新 → `check_project_sources`/`update_project_from_source`;**06 页回滚中心 → `rollback_scan_projects`/`rollback_project_detail`/`rollback_execute_stack_at`(按服务器真实目录,不依赖软件内 projectId)**;05 页日志实时跟随 → `manage_log_stream_start/stop`(manage-logs 事件流,ssh.rs `exec_streaming` 可取消流式);05 页镜像迁移 → `migrate_images`/`migrate_status`(migrate-log/migrate-done 事件,ssh.rs `sftp_download` + `raw_exec_channel`);03 页配置中心 → `config_export_file`/`config_import_file`/`config_wipe`;dock 设置 → `app_settings_get/set` + `update_check`/`update_download`/`update_install`。

详细语义见 [06-部署流程与回滚.md](06-部署流程与回滚.md)(部署/回滚)与 [04-契约参考.md](04-契约参考.md)(命令级)。
