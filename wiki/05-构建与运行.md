# 05 — 构建与运行

## 环境要求

| 组件 | 要求与自检 |
|---|---|
| Windows 10/11 x86_64 | 目标平台(仅 Windows 优先;DPAPI/CREATE_NO_WINDOW 等平台相关) |
| Rust stable(MSVC) | `RUSTUP_HOME` / `CARGO_HOME` 环境变量已设置,`PATH` 含 `%CARGO_HOME%\bin`;MSVC Build Tools 已安装(C++ 桌面开发工作负载)。自检:`rustup show` 应显示 active toolchain,`cargo --version` 正常输出 |
| Node.js + npm | 仅用于 @tauri-apps/cli(devDependency,无运行时依赖)。自检:`node --version` / `npm --version` |
| Docker Desktop | 本机要部署镜像就需要;应用检测不到时给出一键启动/安装指引 |
| 网络代理 | 从 GitHub 下载 crate / NSIS 打包组件超时才需要;设置 `HTTP_PROXY` / `HTTPS_PROXY` 指向本机代理端口。自检:`curl -x %HTTPS_PROXY% -I https://github.com` 返回 HTTP 200 |

### 环境自检(构建前跑一遍)

```powershell
# Rust 工具链 — 报 "no active toolchain" 说明 RUSTUP_HOME 未指向正确目录
rustup show
cargo --version
rustc --version

# Node
node --version
npm --version

# 代理(如使用)— 返回 HTTP 200 即可用
curl -x $env:HTTPS_PROXY -I https://github.com
```

## 常用命令

```bash
# 在项目根目录下执行(含 package.json / src-tauri / ui 的目录)

# 开发(编译 debug 并启动应用;无 dev server,直接加载 ui/)
npm run tauri dev

# 测试(纯函数单测;真机测试 #[ignore] 需加 -- --ignored)
cd src-tauri && cargo test
cd src-tauri && cargo test docker:: -- --ignored   # 需本机 Docker 运行中

# 发布构建(产物见下;release 编译增量约 0.5-3 分钟)
npm run tauri build
```

注意:**不要直接运行 `src-tauri/target/debug/app.exe`**——debug 构建内嵌的是 dev 地址,脱离 `tauri dev` 会报 127.0.0.1 拒绝连接。要看成品直接跑 release exe 或装 NSIS 包。

## 构建产物

```
src-tauri/target/release/app.exe                                    # 主程序 ~17.1MB
src-tauri/target/release/bundle/nsis/DockerDeploy SSH_5.3.0_x64-setup.exe  # 安装包 ~8.2MB
```

- 打包目标:NSIS,语言 SimpChinese,per-user 安装
- `[profile.release]`:strip=true / lto=true / codegen-units=1 / opt-level="s"(体积优先)
- 版本号在 `src-tauri/tauri.conf.json` 的 `version`(当前 5.3.0;git tag 惯例 `v4.5` / `v4.6.0` / `v5.1.0` / `v5.2.0` 形态,v5.2.0 起 push tag 触发 release.yml 自动发版)

## 安装与运行期布局

```
<安装目录>/                       # NSIS 默认 per-user 目录(config/ 需可写)
├── DockerDeploy SSH.exe
├── config/
│   ├── servers.json              # 服务器列表(auth.password_enc / auth.key_pass_enc 为 DPAPI 密文;
│   │                             #   host_key_sha256 为主机密钥 TOFU 指纹)
│   ├── projects.json             # 部署项目(含 service_overrides / 钩子 / 健康检查 / webhook)
│   ├── notify.json               # 通知中心配置(桌面/邮件/事件订阅;email.password_enc 为 DPAPI 密文)
│   ├── settings.json             # 应用设置(closeToTray / proxy;camelCase 字段)
│   ├── deployments.json          # 部署历史(上限 200 条;含 rollback 记录与 release_dir)
│   ├── resume-deploy.json        # 部署断点表(键=服务器|项目|模式,上限 10 条裁最旧;损坏按空表自愈)
│   └── stacks/<uuid>/            # 导入的 compose 副本(docker-compose.yml[+ .env][+ override] + origin.json)
└── logs/app.log                  # 运行日志(Info 级,自动轮转)——排障先看这里
```

- 配置便携:整个目录可拷贝迁移(**跨机器迁移后 DPAPI 密文不可解**——密码需重录;推荐改用 03 页「配置中心」导出/导入:导出文件经导出口令 Argon2id+AES-256-GCM 加密,导入时敏感字段在本机重新 DPAPI 加密,密码可跨机器迁移)
- 原子写临时文件:所有配置 json 写入时先落同目录 `*.tmp` 再 rename 覆盖(瞬时存在,崩溃不留半截文件;`.env` 远端写入同理用 `.env.ddtmp.<PID>` 临时文件)
- 导出备份文件:配置中心导出的 `*.json` 加密信封(结构与普通配置无关,仅导入命令可解)
- `DD_CONFIG_DIR` 环境变量可重定向配置根目录(测试用途)
- debug 构建同理在 `src-tauri/target/debug/` 下生成 config/ 与 logs/
- notify.json 损坏(存在但不可解析)时应用自动回退默认值并**跳过写回**(防覆盖丢 DPAPI 密文),在通知中心显式保存或重启后恢复;settings.json 损坏直接回退默认值(无可再生敏感数据)

## 应用自身的前置条件(内置检测)

| 宿主机 | 服务器(SSH 探测) |
|---|---|
| Docker 已安装(`docker --version`) | docker 命令(缺→一键安装:get-docker.sh,1800s) |
| 守护进程运行中(`docker info`;缺→一键启动,60s 轮询) | docker compose 插件 |
| docker compose 插件 | gzip |
| 临时目录盘剩余空间(前端阈值 2GB) | remote_dir 存在(缺→一键创建) |
| 架构展示(仅信息) | 磁盘剩余(df -PBG;BusyBox 系统拿不到,记 0) |

宿主机未通过 → 镜像/部署页锁定;服务器检测未通过 → 该服务器不可作为部署目标(部署向导会拦)。

## 故障排查速查

| 现象 | 先看 |
|---|---|
| 部署失败 | `logs/app.log` 中 deploy-log 对应时间段;失败步骤名在 deploy-done message 与日志尾部;失败/取消会保留断点,04 页横幅可「从步骤 N 继续」或「放弃断点」 |
| 服务器检测卡住后超时 | 网络可达但 SSH 通道停滞;确认端口/防火墙 |
| 配置丢失/字段被重置 | 是否用了旧快照整对象替换保存(前端约定:新鲜 get_config 就地改) |
| release 下看不到 stdout | 正常——release 无控制台;看 logs/app.log |
| 密码报"解密失败" | 密文绑定同用户同机器;换机器/用户需重录(或用配置中心导出/导入迁移) |
| 连接被拒「服务器主机密钥已变更」 | TOFU 指纹不匹配(重装/换 IP 或中间人);确认无误后 03 页该服务器「重新信任」 |
| 私钥连接失败提示口令错误 | 「私钥口令错误或私钥已损坏」:核对口令;不勾「记住口令」时仅本次生效 |
| 通知邮件发送失败 | 看 logs/app.log 的 warn(分类提示:TLS/超时/认证 5xx/拒信/连接);通知失败不影响部署 |
| 通知配置改了没生效/被还原 | notify.json 曾损坏回退默认值(日志有 warn);在通知中心重新保存一次 |
| 远程管理报「无 Docker 权限」 | 固定文案=SSH 用户无 docker.sock 权限;把用户加入 docker 组或改用 root 连接 |
| 监控无数据 / 自动停止 | 事件 payload 的 error/stopped 字段即原因(连续 3 轮连接失败或权限拒绝后端自停);后端日志记每轮耗时与失败原因 |
| 终端打开即结束 | 看 eof 事件 error(127=容器内无该 shell,126=不可执行);Shell 下拉选「自动(推荐)」让后端探测 |
| 检查更新失败 | 提示已分类(超时/DNS/代理不可达/连接失败;仅 API 回退路径有 403 限流提示,主路径 302 重定向无配额);配代理后用「测试连接」实测一次 |
| 导入配置报「导出口令错误或文件已损坏」 | 口令不对或文件被篡改(GCM 认证失败,二者不可区分);重新导出再试 |
| 清理分析某节显示为空 | 该节查询失败会记入返回的 errors(如旧版 Docker 不支持对应 filter),不影响其余节;build cache 行缺失同理 |
| 批量部署某台失败 | 面板该台徽章 failed + 错误说明;每台独立写历史可单独回滚;余台照常执行(「停止批量」= 当前台跑完即止) |
