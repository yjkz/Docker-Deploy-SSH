# 04 — 契约参考(命令 / 事件 / 配置 Schema)

前后端之间的全部接口。**改动任何一侧必须同步本文档与另一侧。**

命名规则:

- invoke 参数名:JS 侧 **camelCase**(Tauri 2 自动映射 Rust snake_case 形参)
- 对象字段(请求体与返回值/事件载荷):一律 **snake_case**(serde 无 rename_all)
- **camelCase 例外清单**(升级新增,均为 `#[serde(rename_all = "camelCase")]` 的独立契约结构):通知中心(notify.rs 全部视图/入参)、配置中心(`ImportSummary`)、应用设置与检查更新(`AppSettings` / `UpdateInfo`)、回滚列表与回滚中心(`ReleaseBrief` / `RollbackProject` / `RollbackProjectDetail`)、`.env`(`StackEnv`)、批量部署(`BatchDeployRequest` / `BatchDeployEvent`)、断点续传(`ResumeCheckpoint` / `ResumeView`)、清理分析(`CleanupReport` 系列 / `CleanupSections` / `CleanupSectionResult` / `CleanupProject` / `CleanupDiag`)、项目源更新(`ProjectSourceStatus`)、日志实时跟随(`LogsPayload`)、镜像迁移(`MigrateRequest` / `MigrateLogEvent` / `MigrateDoneEvent`)、项目跨服务器迁移(`MigrateProjectRequest` / `MigrateProjectPlan` 系列 / `MigrateProjectLogEvent` / `MigrateProjectDoneEvent`)。除下表明确标注 camelCase 的结构外,其余一律 snake_case(**前端读错命名会静默得到 `undefined`,清理分析计数曾因此恒为 0**)
- 枚举字符串:`"Key"/"Password"`、`"Local"/"Pull"`、`"Exact"/"RepoOnly"/"Missing"`
- 远程管理模块上游约定:`docker --format json` 的输出是 **NDJSON 且字段 PascalCase**(ID 字段全大写 `ID`),由 Rust 结构体(`#[serde(rename_all = "PascalCase")]` + `#[serde(rename = "ID")]`)解析后**转为 snake_case 再返回前端**;前端永远只见 snake_case

```jsonc
// DeployRequest(单镜像)
{ "image": "myapp:latest", "repository": "myapp", "server_id": "...",
  "project_id": "...", "use_date_tag": true, "password_plain": null,
  "skip_unchanged": true }        // 智能传输开关(缺省=false 向后兼容)

// StackDeployRequest(整栈)
{ "project_id": "...", "server_id": "...", "password_plain": null,
  "services": [ { "service": "web", "image": "myapp:latest", "mode": "Local" },
                { "service": "db", "image": "mysql:8",      "mode": "Pull"  } ],
  "skip_unchanged": true,         // 未变化服务跳过打包/上传/装载
  "force_archive": false }        // 强制留档:未变化镜像仍打包进发布目录供回滚,仅跳过装载

// BatchDeployRequest(批量;camelCase;single 专用字段与 stack 专用字段按 mode 取用)
{ "mode": "single"|"stack", "projectId": "...", "serverIds": ["id1", "id2"],  // 入口去重
  "image": "myapp:latest", "repository": "myapp", "useDateTag": true,          // 仅 single
  "services": [ /* 同 StackServiceChoice,所有目标共用一套分类 */ ],            // 仅 stack
  "forceArchive": false,                                                       // 仅 stack
  "skipUnchanged": true, "passwordPlain": null }                               // 所有目标共用
```

**智能传输(skip_unchanged / force_archive)**:判定依据 = 镜像 ID(配置摘要,内容寻址)——远端 `docker images --no-trunc --format '{{json .}}'` 取**完整 64 位 ID** vs 本地 `image_id_by_ref`(`--no-trunc` 同口径),剥 `sha256:` 前缀忽略大小写比较(`same_image_id`)。单镜像模式仅 `use_date_tag=false` 生效(日期标签必为全新 tag);远端不存在/取不到 ID 时回退全量传输。整栈模式行为矩阵(skip_unchanged × force_archive,均缺省 false):全未变化时打包/上传/装载三步全跳;force_archive 时未变化镜像仍打包上传进发布目录(供回滚 `docker load`)但跳过装载。

部署中禁止再次调用 deploy/deploy_stack/rollback_execute_*(后端全局单取消标志会被重置)。

### 清理分析(commands.rs,2 个;阶段八,第三批重构;`passwordPlain` 约定同服务器操作)

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `cleanup_preview` | `{ serverId, passwordPlain?, scanRoot? }` | `CleanupReport`(camelCase) | **只读分析**:无标签镜像 / 停止容器 / 未使用卷 / build cache + **分项目可清理项**;`scanRoot` 缺省用服务器 `remote_dir`,可传 `/home` 等逐层向下扫描(深度 ≤4,排除 `releases/` 与 `.git`);各节独立查询互不阻断,单条命令失败记入 `warnings` 并在 `diagnostics` 留证据;不做任何清理 |
| `cleanup_execute` | `{ serverId, passwordPlain?, sections: CleanupSections }` | `CleanupSectionResult[]`(camelCase) | 按**显式目标列表**逐条删除(300s/节);逐节输出流式推 `server-log`;单节失败(含传输层错误)不中断后续;无任何可执行目标则 Err |

**无标签镜像为什么不用 `docker images -f dangling=true`**:该过滤在 BuildKit / containerd image store 下常返回空,而 `docker images` 明明列出 `<none>:<none>` 条目 —— 表现为「有悬空镜像却识别不到」。现改为全量拉取 `docker images --no-trunc --format '{{json .}}'` 后客户端过滤 `Repository == "<none>" || Tag == "<none>"`,并用容器引用集合(`docker ps -a --no-trunc` + `docker inspect --format '{{.Image}}'`)标记在用项,只有未被任何容器(含已停止)引用者才可勾选。

**为什么逐条删除而非 `prune -f`**:prune 的删除范围由 docker 自行判定,与预览勾选项未必一致(如 `volume prune` 会连未列出的未使用卷一起删)。逐条删除让执行结果与用户所见一一对应。

### 一键回滚(commands.rs,4 个;复用 deploy-log / deploy-done 事件体系)

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `rollback_list_releases` | `{ serverId, passwordPlain?, projectId }` | `ReleaseBrief[]`(camelCase) | 列出服务器 releases 目录(新 → 旧);逐目录列文件 + 读 manifest.json 取服务名;**无 manifest(旧版本发布)优雅降级**(services 空、hasManifest=false);releases 目录不存在 → 空列表非错误 |

### 独立回滚中心(commands.rs,3 个;第三批,06 页;按服务器真实目录工作)

与上面 4 个命令的区别:这一组**不依赖应用内 `project_id`**,释出目录与 compose 目标都由传入的**项目目录**决定,因此服务器上任何含 compose 的目录(哪怕不是本应用部署的)都能回滚。

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `rollback_scan_projects` | `{ serverId, passwordPlain?, scanRoot? }` | `RollbackProject[]`(camelCase) | 项目清单 = compose 文件扫描(深度 ≤4,排除 `releases/`、`.git`)+ `docker ps` 的 `com.docker.compose.project.working_dir` label 合并去重;每项含 `dir` / `composeFile` / `releases` / `releaseCount` / `latestRelease` / `runningContainers` / `appProject`(软件内项目名,仅标注) |

额外搬运 compose 三件套、数据卷、发布归档,并负责改绑配置与写迁移历史。

| 命令 | 参数 | 返回 | 说明 |

| `migrate_project_preview` | `{ projectId, sourceServerId, targetServerId, includeVolumes?, releaseCount? }` | `MigrateProjectPlan`(camelCase) | **只读预检**:连源服务器读取**实际部署的** compose(`<源目录>/docker-compose.yml`,本机副本不作依据,故手工项目同样可用),解析出镜像清单/卷清单/近 N 个归档,并收集警告与阻断项。不产生任何副作用 |
| `migrate_project_start` | `{ req: MigrateProjectRequest }`(camelCase) | `null`(同步) | 执行迁移:卷导出停机窗口最小化(停 → 导出 → **立即恢复源** → 再传长耗时的镜像/归档)、源侧资产保留不动、完成后改绑 `default_server_id` 并写一条 `mode="migrate"` 历史。进度经 `migrate-project-log`、结果经 `migrate-project-done` |

```jsonc
{ "projectId": "p1", "projectName": "zetok",
  "sourceServerName": "服务器A", "targetServerName": "服务器B",
  "sourceRemoteDir": "/opt/zetok", "targetRemoteDir": "/opt/zetok",

                 "kind": "Named",        // "Named" | "BindRelative"
                 "size": "1.2 GB",       // 取不到为 null
                 "renamed": false } ],   // 两机目录名不同导致卷名变化 ⇒ true
  "releases": [ { "ts": "20260910-120000", "size": "800 MB", "services": ["web","db"] } ],
  "totalBytes": 2147483648,          // 取不到体积时为 null
  "warnings": ["目标服务器已存在 docker-compose.yml,执行时将被覆盖(原文件不备份)"],
  "errors": [] }                     // 非空 = 不允许执行(如源与目标目录相同)

{ "migrateId": number, "line": "[12:00:00] …" }

  "warnings": ["卷 zetok_pgdata 在目标服务器将导入为 prod_pgdata"] }
```

**哪些卷会搬**:命名卷(`pgdata` 形式,实际名 `<项目目录名>_<卷名>`)与项目目录内的相对
路径挂载(`./data`);**不搬**宿主绝对路径(如 `/etc/localtime`,可能是系统文件)与
顶层声明 `external: true` 的卷(可能是多项目共享)—— 这两类只出现在 `warnings` 里,
由用户自行处理。

**卷名跨机推导**:两机部署目录名不同时,同一 compose 卷在两台机器上的实际卷名不同
(如 `zetok_pgdata` vs `prod_pgdata`)。执行时**按目标侧自己的卷名创建并导入**
(数据不关心名字,目标是 compose 找得到),并在 `warnings` 里明确提示;
compose 顶层 `volumes:` 写了 `name:` 覆盖时两机同名,不受影响。

**执行时序与停机窗口**:`②源 compose stop → ③导出卷 → ④源 compose start`(停机窗口
仅卷导出时长)→ ⑤传输镜像/卷包/归档(源已恢复运行)→ ⑥目标装载 → ⑦compose 与归档落盘
→ ⑧`compose up -d` → ⑨清理两端临时产物 → ⑩改绑配置与写历史。
**④ 无条件执行**:任何导出失败路径都先尝试恢复源服务再返回错误,避免用户的服务停在停止态。

**数据卷导出依赖临时容器**:宿主机不一定有 tar(`docker run -v` 是唯一稳妥路径),
候选镜像链为服务器上已存在的 `busybox:latest` → `alpine:latest` → `ubuntu:latest`,
都没有则 `docker pull busybox`(约 2MB,需服务器出网),仍失败则明确报错并给出建议。

**与部署历史**:成功写一条 `mode="migrate"` 记录(server_name 形如「源 → 目标」),
前端历史表显示「迁移」徽标且**不提供回滚按钮**(回滚语义对该记录无意义 —— 源服务器资产并未删除)。

## 4. 全局错误约定

- 所有命令 `Result<T, String>`,错误信息**中文带上下文**
- Promise reject 的字符串直接 toast/错误框展示,不再加工
- 取消统一文案 `"部署已取消"`;SSH 超时 `"连接超时(15 秒):…"` / 命令超时按常量名区分
- `deploy-done` 失败 message 为中文错误(含失败环节上下文);日志另有 `部署失败: <原因>` 行
- **主机密钥变更**(TOFU 不匹配)固定文案:「服务器主机密钥已变更!可能为服务器重装/换 IP,也可能存在中间人风险。如确认无误,请在服务器管理中重新信任该主机。」(ssh.rs `UnknownKey` 映射;前端引导 03 页「重新信任」)
- **私钥口令错误**固定文案:「私钥口令错误或私钥已损坏 (<路径>)」;加密私钥未提供口令:「私钥已加密,请输入私钥口令…」
- **导出文件口令错误/损坏**统一文案:「导出口令错误或文件已损坏」(GCM 认证失败,二者不可区分,有意为之)
- **远程管理权限兜底**:非 root 用户无 docker.sock 权限时,统一返回固定文案「当前 SSH 用户无 Docker 权限(无法访问 /var/run/docker.sock),请将该用户加入 docker 组或使用 root 用户连接」(manage.rs `PERM_DENIED_MSG`,各命令与监控流共用)
- 远程管理超时梯度:建连 15s / 常规 exec 60s / 镜像 pull 300s / 栈 up-down 120s;错误形如 `<动作>超时(60 秒):<提示>`

## 5. 变更流程清单(改契约时)

1. 改 Rust struct/命令 → `cargo test` 全绿
2. 改对应 JS 调用与字段读取 → `node --check` + id 引用核对
3. 更新本文档对应表格
4. 跑 `npm run tauri build` 冒烟 + 至少一次真实页面操作
5. 远程管理新增命令:同时核对 `lib.rs` generate_handler 注册、manage 页 Tab 路由(switchTab)、自动刷新路径(refreshAll)与离页清理(onLeave)
6. 新增命令注意命名口径:默认 snake_case;仅「camelCase 例外清单」中的新契约结构用 `rename_all = "camelCase"`
7. **改返回字段名(camelCase ↔ snake_case)后必须逐处核对前端读取点**:命名不匹配不会报错,只会静默得到 `undefined` —— 清理分析计数曾因此恒为 0(v5.3.2 → v5.4.0 修复)。
8. 新增独立页面模块:同时核对 `index.html`(dock 按钮 + section + `<script>`)、`app.js` 的 `LOCKED_PAGES`(纯远程模块勿加)、模块内 pagechange 进出与离页清理。
