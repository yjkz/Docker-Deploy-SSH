# 04 — 契约参考(命令 / 事件 / 配置 Schema)

> 对齐版本:v6.18.0(测试基线 534 passed / 15 ignored;命令 122 个)

前后端之间的全部接口。**改动任何一侧必须同步本文档与另一侧。**

命名规则:

- invoke 参数名:JS 侧 **camelCase**(Tauri 2 自动映射 Rust snake_case 形参)
- 对象字段(请求体与返回值/事件载荷):一律 **snake_case**(serde 无 rename_all)
- **camelCase 例外清单**(升级新增,均为 `#[serde(rename_all = "camelCase")]` 的独立契约结构):通知中心(notify.rs 全部视图/入参)、配置中心(`ImportSummary`)、应用设置与检查更新(`AppSettings` / `UpdateInfo` / `DownloadedUpdate`)、回滚列表与回滚中心(`ReleaseBrief` / `RollbackProject` / `RollbackProjectDetail` / `RollbackReleaseDetail` / `RollbackTagDetail` / `ReleaseNotes` / `ReleaseNotesRequest` / `ReleaseNotesSaved`)、`.env`(`StackEnv`)、批量部署(`BatchDeployRequest` / `BatchDeployEvent`)、断点续传(`ResumeCheckpoint` / `ResumeView`)、清理分析(`CleanupReport` 系列 / `CleanupSections` / `CleanupSectionResult` / `CleanupProject` / `CleanupDiag`)、项目源更新(`ProjectSourceStatus`)、日志实时跟随(`LogsPayload`)、镜像迁移(`MigrateRequest` / `MigrateLogEvent` / `MigrateDoneEvent`)、项目跨服务器迁移(`MigrateProjectRequest` / `MigrateProjectPlan` 系列 / `MigrateProjectLogEvent` / `MigrateProjectDoneEvent`)。除下表明确标注 camelCase 的结构外,其余一律 snake_case(**前端读错命名会静默得到 `undefined`,清理分析计数曾因此恒为 0**)
- 枚举字符串:`"Key"/"Password"`、`"Local"/"Pull"`、`"Exact"/"RepoOnly"/"Missing"`
- 远程管理模块上游约定:`docker --format json` 的输出是 **NDJSON 且字段 PascalCase**(ID 字段全大写 `ID`),由 Rust 结构体(`#[serde(rename_all = "PascalCase")]` + `#[serde(rename = "ID")]`)解析后**转为 snake_case 再返回前端**;前端永远只见 snake_case

```jsonc
// DeployRequest(单镜像)
{ "image": "myapp:latest", "repository": "myapp", "server_id": "...",
  "project_id": "...", "use_date_tag": true, "password_plain": null,
  "skip_unchanged": true }        // 智能传输开关(缺省=false 向后兼容)

// StackDeployRequest(整栈)
{ "project_id": "...", "server_id": "...", "password_plain": null,
  "services": [ { "service": "web", "image": "myapp:latest", "mode": "Local" },
                { "service": "db", "image": "mysql:8",      "mode": "Pull"  } ],
  "skip_unchanged": true,         // 未变化服务跳过打包/上传/装载
  "force_archive": false }        // 强制留档:未变化镜像仍打包进发布目录供回滚,仅跳过装载

// BatchDeployRequest(批量;camelCase;single 专用字段与 stack 专用字段按 mode 取用)
{ "mode": "single"|"stack", "projectId": "...", "serverIds": ["id1", "id2"],  // 入口去重
  "image": "myapp:latest", "repository": "myapp", "useDateTag": true,          // 仅 single
  "services": [ /* 同 StackServiceChoice,所有目标共用一套分类 */ ],            // 仅 stack
  "forceArchive": false,                                                       // 仅 stack
  "skipUnchanged": true, "passwordPlain": null }                               // 所有目标共用
```

**智能传输(skip_unchanged / force_archive)**:判定依据 = 镜像 ID(配置摘要,内容寻址)——远端 `docker images --no-trunc --format '{{json .}}'` 取**完整 64 位 ID** vs 本地 `image_id_by_ref`(`--no-trunc` 同口径),剥 `sha256:` 前缀忽略大小写比较(`same_image_id`)。单镜像模式仅 `use_date_tag=false` 生效(日期标签必为全新 tag);远端不存在/取不到 ID 时回退全量传输。整栈模式行为矩阵(skip_unchanged × force_archive,均缺省 false):全未变化时打包/上传/装载三步全跳;force_archive 时未变化镜像仍打包上传进发布目录(供回滚 `docker load`)但跳过装载。

部署中禁止再次调用 deploy/deploy_stack/rollback_execute_*(后端全局单取消标志会被重置)。

### 部署断点续传(commands/,3 个;阶段六)

单发部署(deploy / deploy_stack)每个步骤边界落盘断点到 `config/resume-deploy.json`(键 `server_id|project_id|mode`,上限 10 条裁最旧);成功清理+删断点,取消/失败保留。断点记录 `step_next`(失败步骤号=续传起点)与步骤产物 `artifacts`。

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `deploy_resume_status` | `{ serverId, projectId }` | `Option<ResumeView>`(camelCase) | 查询该服务器+项目是否存在断点(单镜像/整栈两条键取 ts 最新);无断点返回 null |
| `deploy_resume_start` | `{ key, passwordPlain? }` | `null`(同步) | 从断点续传:校验断点与服务器/项目仍存在 → 构造与单发一致的请求走 `spawn_deploy_task`(事件/部署历史/通知语义与正常部署**完全一致**);管线从 step_next 起,对已完成产物幂等化复用(本地 tar 存在且大小匹配 / 远端 tar `sftp_stat_size` 断点续传 / load 前远端 ID 比对跳过);新部署同键覆盖旧断点 |
| `deploy_resume_discard` | `{ key }` | `null` | 放弃断点:删断点 + 删本地临时 tar + 尽力删远端产物(单镜像 `/tmp` tar;整栈 releases 半成品目录;连接失败等一律忽略不报错) |

```jsonc
// ResumeView(deploy_resume_status 元素;camelCase)
{ "key": "server_id|project_id|mode",  // 传给 start/discard 的断点键
  "mode": "single"|"stack", "stepNext": number,   // 下一个待执行步骤号(1 起)

```

批量部署与断点续传(第十四批更正):批量由前端队列逐台复用单发 `deploy`/`deploy_stack`,后端恒 `checkpoint=true` → **批量恒落断点**;失败/被取消的台保留断点,面板提供「续传此台」(单台)与「续传未完成服务器(N 台)」(一键批量,点续传时用 `deploy_resume_status` 现查)两个入口,续传走 `deploy_resume_start`(与单发同管线)。原「批量不落断点」只描述未接入的死代码 `deploy_batch`,与线上批量无关。

### 清理分析(commands/,2 个;阶段八,第三批重构;`passwordPlain` 约定同服务器操作)

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `cleanup_preview` | `{ serverId, passwordPlain?, scanRoot? }` | `CleanupReport`(camelCase) | **只读分析**:无标签镜像 / 停止容器 / 未使用卷 / build cache + **分项目可清理项**;`scanRoot` 缺省用服务器 `remote_dir`,可传 `/home` 等逐层向下扫描(深度 ≤4,排除 `releases/` 与 `.git`);各节独立查询互不阻断,单条命令失败记入 `warnings` 并在 `diagnostics` 留证据;不做任何清理 |
| `cleanup_execute` | `{ serverId, passwordPlain?, sections: CleanupSections }` | `CleanupSectionResult[]`(camelCase) | 按**显式目标列表**逐条删除(300s/节);逐节输出流式推 `server-log`;单节失败(含传输层错误)不中断后续;无任何可执行目标则 Err |

**无标签镜像为什么不用 `docker images -f dangling=true`**:该过滤在 BuildKit / containerd image store 下常返回空,而 `docker images` 明明列出 `<none>:<none>` 条目 —— 表现为「有悬空镜像却识别不到」。现改为全量拉取 `docker images --no-trunc --format '{{json .}}'` 后客户端过滤 `Repository == "<none>" || Tag == "<none>"`,并用容器引用集合(`docker ps -a --no-trunc` + `docker inspect --format '{{.Image}}'`)标记在用项,只有未被任何容器(含已停止)引用者才可勾选。

**为什么逐条删除而非 `prune -f`**:prune 的删除范围由 docker 自行判定,与预览勾选项未必一致(如 `volume prune` 会连未列出的未使用卷一起删)。逐条删除让执行结果与用户所见一一对应。

```jsonc
{ "danglingImages": [ { "id": "sha256:...", "repository": "<none>", "tag": "<none>",
                        "size": "106.3MB", "inUse": false } ],
  "stoppedContainers": [ { "id": "...", "names": "...", "image": "...", "status": "Exited (0) ..." } ],
  "unusedVolumes": [ { "name": "..." } ],
  "buildCacheSize": "1.234GB",
  // 分项目(第三批):以服务器真实目录为准;归档与标签按 compose 内 image 仓库名归属
  "projects": [ { "dir": "/home/henghao/zetok", "composeFile": "/home/henghao/zetok/docker-compose.yml",
```

```jsonc
                 "size": "1.2 GB",       // 取不到为 null
                 "renamed": false } ],   // 两机目录名不同导致卷名变化 ⇒ true
  "releases": [ { "ts": "20260910-120000", "size": "800 MB", "services": ["web","db"] } ],
  "totalBytes": 2147483648,          // 取不到体积时为 null

  "warnings": ["卷 zetok_pgdata 在目标服务器将导入为 prod_pgdata"] }
```

**哪些卷会搬**:命名卷(`pgdata` 形式,实际名 `<项目目录名>_<卷名>`)与项目目录内的相对
路径挂载(`./data`);**不搬**宿主绝对路径(如 `/etc/localtime`,可能是系统文件)与
顶层声明 `external: true` 的卷(可能是多项目共享)—— 这两类只出现在 `warnings` 里,
由用户自行处理。

**卷名跨机推导**:两机部署目录名不同时,同一 compose 卷在两台机器上的实际卷名不同
(如 `zetok_pgdata` vs `prod_pgdata`)。执行时**按目标侧自己的卷名创建并导入**
(数据不关心名字,目标是 compose 找得到),并在 `warnings` 里明确提示;
compose 顶层 `volumes:` 写了 `name:` 覆盖时两机同名,不受影响。

**执行时序与停机窗口**:`②源 compose stop → ③导出卷 → ④源 compose start`(停机窗口
仅卷导出时长)→ ⑤传输镜像/卷包/归档(源已恢复运行)→ ⑥目标装载 → ⑦compose 与归档落盘
→ ⑧`compose up -d --remove-orphans --pull never --no-build`(第三十一/三十二批:目标镜像全部来自 load,隐式拉取/构建都等于「搬的不是源上的版本」)→ ⑨清理两端临时产物 → ⑩改绑配置与写历史。
**④ 无条件执行**:任何导出失败路径都先尝试恢复源服务再返回错误,避免用户的服务停在停止态。

**数据卷导出依赖临时容器**:宿主机不一定有 tar(`docker run -v` 是唯一稳妥路径),
候选镜像链为服务器上已存在的 `busybox:latest` → `alpine:latest` → `ubuntu:latest`,
都没有则 `docker pull busybox`(约 2MB,需服务器出网),仍失败则明确报错并给出建议。

**与部署历史**:成功写一条 `mode="migrate"` 记录(server_name 形如「源 → 目标」),
前端历史表显示「迁移」徽标且**不提供回滚按钮**(回滚语义对该记录无意义 —— 源服务器资产并未删除)。

## 4. 全局错误约定

- 所有命令 `Result<T, String>`,错误信息**中文带上下文**
- Promise reject 的字符串直接 toast/错误框展示,不再加工(`errText` 自动剥码标记,展示层永不带码)
- **错误码(第十六批,v5.15.0)**:错误串可带头部标记 `[dderr:<code>]`(单元分隔符 + 码名;UI 不渲染),**流程判定一律按码、不认文案**。生产用 `errors::tagged(code, msg)`,判定用 `errors::code_of(s)`(Rust)/ `parseErrCode(s)`(JS);无码/未知码一律按「无码」降级(前后端版本错配安全)。**加类**:errors.rs 枚举加变体 + `as_str`/`from_str_raw` 各一行,前端按需加分支;**删类**:删变体后编译器穷尽检查逐点报出使用处。码表:

  | 码 | 类别 | 典型来源 |
  |---|---|---|
  | `canceled` | 用户取消 | 部署/回滚/迁移取消(`errors::cancelled`) |
  | `transport` | SSH/SFTP 传输层失败 | 通道打开/命令发送失败、连接断开(ssh.rs 各 exec/sftp 生产点;监控重连按此计数) |
  | `auth` | SSH 认证失败 | 密码/公钥被拒、私钥口令错误、主机密钥变更(ssh.rs connect) |
  | `perm_denied` | Docker 权限拒绝 | 无 docker.sock 权限(`errors::perm_denied`;监控立即停止) |
  | `timeout` | 超时 | `with_timeout` 全部超时点 |
  | `network` | HTTP 网络失败 | 检查更新的 reqwest 错误(预留;update.rs 未挂,见下方说明) |
  | `protocol` | 远端命令非零退出 | exec_json_list / docker stats 退出码 ≠0 且 ≠-1 |
  | `config` | 配置缺失/非法 | 服务器配置字段缺失等 |
  | `parse` | 解析失败 | compose/NDJSON/JSON 解析 |
  | `fs` | 文件系统失败 | SFTP 上传下载、本地读写、私钥文件读取 |
  | `input` | 用户输入不合法 | 表单值/参数校验 |
  | `internal` | 内部错误 | panic 兜底(预留) |
| `rollback_precheck` | 回滚可用性预检未通过(归档里有服务回不去,**或存在 .env 插值漂移** —— v6.12.0);前端据此弹「仍要回滚(部分)」确认,带 `allowPartial=true` 重发 |

- **判定点迁移(第十六批)**:后端 `e == CANCELLED_MSG` → `code_of(e) == Some(Cancelled)`(mod.rs/deploy.rs/rollback.rs 共 4 处);`is_transport_error` 文案匹配 → 按 `transport`/`timeout` 码判定(manage_stats.rs);前端 `'部署已取消'` 逐字匹配 → `parseErrCode(p) === 'canceled'` **并保留文案回退**(deploy.js 横幅/批量循环/历史徽章 —— 回退兼容旧格式历史记录与新码缺失场景)
- **事件 payload 的 errorCode 字段(camelCase,可选)**:`deploy-done` 失败/取消时 `errorCode` = 码名(成功省略);`manage-stats` 失败轮 `errorCode` = 码名(成功省略)。前端优先读字段,缺失时回退对 message 做 `parseErrCode`,再回退文案匹配(v6.1.4 起由 app.js `window.errCodeOf(payload)` 统一实现,deploy.js 三处 deploy-done 消费点已接线)
- **`manage-stats` 的 aggregate 字段(第十七批,camelCase)**:成功轮附容器级聚合 `{ count, topCpu: [{name, cpuPercent, memUsage}] × ≤3, topMem: [同构] × ≤3 }`(Top3 CPU 按数值降序,解析失败的行排末尾);失败轮为默认值(count=0)。旧版后端无此字段 → 前端隐藏聚合条(版本错配安全)
- **`manage_stack_env_read` 返回(第十七批)**:增 `notUtf8: bool`(文件含非 UTF-8 字节)与 `rawB64: string`(原始字节 base64,仅 notUtf8 时非空);`manage_stack_env_save` 增可选入参 `rawB64` —— 非空时跳过 content 直接落盘原始字节(未改动保存的无损回写路径)
- **`app_settings_set` 增 `probeIntervalMins`(第十七批,camelCase)**:定时探活间隔分钟,0 = 关(默认);保存时后端自动启停探活任务。**通知事件类型增 `probe`**:订阅开关 `events.onProbe`(notify.json,默认关)—— 服务器探活状态翻转(在线→离线 / 离线→恢复)时分发,不做每轮轰炸
- **`app_settings_set` 增 `alertIntervalMins` / `alertDiskPercent` / `alertMemPercent` / `alertCpuPercent`(第二十四批,camelCase)**:资源告警采样间隔分钟(0 = 关,默认)+ 三维阈值(默认 90%,0 = 该项不告警);保存时后端自动启停告警采样任务。**通知事件类型增 `alert`**:订阅开关 `events.onAlert`(notify.json,默认关)—— 磁盘/内存/CPU **连续 2 轮**超阈时分发(防瞬态尖峰;回落单轮即发「已恢复」);采样经 SSH 逐台执行,与部署/回滚/迁移互斥(执行中被跳过,下轮重试)
- **文案匹配的合法存留区**:匹配**远端工具原样输出**的判定无法挂码 —— `is_docker_perm_denied`(docker 的 "permission denied … docker.sock")与 `augment_pull_error`(docker pull 的 "401/Unauthorized/denied")保留,属外部工具输出解析而非前后端契约
- 取消统一文案 `"部署已取消"`(文案本体 `CANCELLED_MSG`,经 `errors::cancelled()` 挂码);SSH 超时 `"连接超时(15 秒):…"` / 命令超时按常量名区分
- `deploy-done` 失败 message 为中文错误(含失败环节上下文);日志另有 `部署失败: <原因>` 行
- **主机密钥变更**(TOFU 不匹配)固定文案:「服务器主机密钥已变更!可能为服务器重装/换 IP,也可能存在中间人风险。如确认无误,请在服务器管理中重新信任该主机。」(ssh.rs `UnknownKey` 映射;前端引导 03 页「重新信任」)
- **私钥口令错误**固定文案:「私钥口令错误或私钥已损坏 (<路径>)」;加密私钥未提供口令:「私钥已加密,请输入私钥口令…」
- **导出文件口令错误/损坏**统一文案:「导出口令错误或文件已损坏」(GCM 认证失败,二者不可区分,有意为之)
- **远程管理权限兜底**:非 root 用户无 docker.sock 权限时,统一返回固定文案「当前 SSH 用户无 Docker 权限(无法访问 /var/run/docker.sock),请将该用户加入 docker 组或使用 root 用户连接」(manage.rs `PERM_DENIED_MSG`,各命令与监控流共用)
- 远程管理超时梯度:建连 15s / 常规 exec 60s / 镜像 pull 300s / 栈 up-down 120s;错误形如 `<动作>超时(60 秒):<提示>`

## 5. 变更流程清单(改契约时)

1. 改 Rust struct/命令 → `cargo test` 全绿
2. 改对应 JS 调用与字段读取 → `node --check` + id 引用核对
3. 更新本文档对应表格
4. 跑 `npm run tauri build` 冒烟 + 至少一次真实页面操作
5. 远程管理新增命令:同时核对 `lib.rs` generate_handler 注册、manage 页 Tab 路由(switchTab)、自动刷新路径(refreshAll)与离页清理(onLeave)
6. 新增命令注意命名口径:默认 snake_case;仅「camelCase 例外清单」中的新契约结构用 `rename_all = "camelCase"`
7. **改返回字段名(camelCase ↔ snake_case)后必须逐处核对前端读取点**:命名不匹配不会报错,只会静默得到 `undefined` —— 清理分析计数曾因此恒为 0(v5.3.2 → v5.4.0 修复)。
8. 新增独立页面模块:同时核对 `index.html`(dock 按钮 + section + `<script>`)、`app.js` 的 `LOCKED_PAGES`(纯远程模块勿加)、模块内 pagechange 进出与离页清理。
