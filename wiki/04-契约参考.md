# 04 — 契约参考(命令 / 事件 / 配置 Schema)

前后端之间的全部接口。**改动任何一侧必须同步本文档与另一侧。**

命名规则:

- invoke 参数名:JS 侧 **camelCase**(Tauri 2 自动映射 Rust snake_case 形参)
- 对象字段(请求体与返回值/事件载荷):一律 **snake_case**(serde 无 rename_all)
- 枚举字符串:`"Key"/"Password"`、`"Local"/"Pull"`、`"Exact"/"RepoOnly"/"Missing"`

---

## 1. 命令(19 个)

### 配置

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `get_config` | — | `AppConfig` | 读 servers.json + projects.json |
| `save_config_cmd` | `{ cfg: AppConfig }` | `null` | **全量原子写回**(前端必须先新鲜 get_config 再改) |
| `encrypt_password` | `{ plain: string }` | `string` | DPAPI 加密 → base64;存入 `auth.password_enc`。**没有对应解密命令** |

### 环境检测 / Docker

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `host_check` | — | `HostCheckReport` | 宿主机检测;检测页加载即调 |
| `get_history` | — | `DeployRecord[]` | 部署历史(倒序=最新在前;上限 200 条) |
| `start_docker` | — | `null` | 一键启动守护进程(至多 60s,阻塞返回) |
| `list_images` | — | `ImageInfo[]` | 本机镜像列表 |

### 服务器操作(全部要求环境检测语义:建连 15s / exec 60s 超时)

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `test_server` | `{ serverId, passwordPlain? }` | `ServerCheckReport` | 连接 + 服务器环境检测 |
| `server_env_check` | `{ serverId, passwordPlain? }` | `ServerCheckReport` | 与 test_server 等价 |
| `install_server_docker` | `{ serverId, passwordPlain? }` | `null` | SSH 执行官方安装脚本(1800s 超时);输出经 `server-log` 事件逐行推送 |
| `create_remote_dir` | `{ serverId, passwordPlain? }` | `null` | 远端 `mkdir -p remote_dir` |
| `prune_server` | `{ serverId, passwordPlain? }` | `null` | 服务器清理(image+container prune,300s);输出经 `server-log` |

`passwordPlain` 仅 Password 认证且用户本次输入新密码时传;一般省略(后端 DPAPI 解密已存密文)。Key 认证时后端忽略该参数。

### compose / 整栈

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `preview_compose` | `{ sourcePath }` | `ComposeStack` | 静态只读解析任意 compose(含本地镜像三级匹配),供导入预览;不落盘 |
| `import_compose` | `{ sourcePath, name }` | `ProjectConfig` | 校验+解析 → 复制 compose(及同目录 .env)到 `config/stacks/<uuid>/` → 以默认 service_overrides 建新项目持久化 → 返回完整项目 |
| `parse_compose` | `{ projectId }` | `ComposeStack` | 按已存项目解析(list_images 一次 + service_overrides 覆盖);**每次调用实时重算本地匹配**(含默认镜像名兜底扫描) |
| `preview_stack_changes` | `{ serverId, projectId, passwordPlain? }` | `StackPreview` | **部署预览(dry-run,独立功能)**:远端容器/镜像 vs 本地解析,五态分类;只读不落盘 |

### 部署

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `deploy` | `{ req: DeployRequest }` | `null`(同步) | 单镜像部署;立即返回,进度/结果走事件 |
| `deploy_stack` | `{ req: StackDeployRequest }` | `null`(同步) | 整栈部署;同上 |
| `cancel_deploy` | — | `null` | 置取消标志;协作式——步骤边界/exec 输出行时生效 |

```jsonc
// DeployRequest(单镜像)
{ "image": "myapp:latest", "repository": "myapp", "server_id": "...",
  "project_id": "...", "use_date_tag": true, "password_plain": null }

// StackDeployRequest(整栈)
{ "project_id": "...", "server_id": "...", "password_plain": null,
  "services": [ { "service": "web", "image": "myapp:latest", "mode": "Local" },
                { "service": "db", "image": "mysql:8",      "mode": "Pull"  } ] }
```

部署中禁止再次调用 deploy/deploy_stack(后端全局单取消标志会被重置)。

## 2. 事件(4 个)

| 事件 | 载荷 | 说明 |
|---|---|---|
| `deploy-progress` | `{ step: number, total: number, message: string }` | 单镜像 total=5(打标签/导出压缩/上传镜像/同步文件/服务器部署);整栈 total=6(分类确认/打包/上传/装载/拉取/启动);step 从 1 开始,只在步骤**开始**时发 |
| `deploy-log` | `string` | 一行日志,带 `[HH:MM:SS]` 前缀 |
| `deploy-done` | `{ success: boolean, message: string }` | **任何路径恰好一次**;取消固定 `message === "部署已取消"`(前端据此显示黄条) |
| `server-log` | `string` | install_server_docker 的逐行输出 |

`deploy` / `deploy_stack` 同步返回 null 不代表成功;成功/失败仅以 `deploy-done` 为准。

## 3. 返回类型字段表

```jsonc
// HostCheckReport
{ "docker_installed": bool, "daemon_running": bool, "compose_ok": bool,
  "docker_version": string|null, "arch": string|null,
  "disk_free_gb": number|null, "error": string|null }

// ImageInfo
{ "repository": string, "tag": string, "size_bytes": number,  // 1024 进制换算
  "created": string, "id": string }

// ServerCheckReport
{ "docker": bool, "compose": bool, "gzip": bool,
  "remote_dir_exists": bool, "disk_free_gb": number,           // 解析失败=0.0 且 errors 有条目
  "errors": string[] }

// AppConfig
{ "servers": ServerConfig[], "projects": ProjectConfig[] }

// ServerConfig
{ "id": string, "name": string, "host": string, "port": number, // u16,1-65535
  "username": string,
  "auth": { "auth_type": "Key"|"Password", "key_path": string|null, "password_enc": string|null },
  "remote_dir": string }

// ProjectConfig
{ "id": string, "name": string, "image_filter": string, "compose_file": string,
  "file_mappings": [ { "local": string, "remote": string, "is_dir": bool } ],
  "service_overrides": [ { "service": string, "mode": "Local"|"Pull" } ],  // serde default
  "health_wait_secs": number,          // 0=关闭健康检查;>0=up 后轮询等待上限(秒)
  "pre_deploy_cmd": string|null,       // pre 钩子(失败中止部署)
  "post_deploy_cmd": string|null,      // post 钩子(失败仅告警)
  "notify_webhook": string|null }      // 部署结束 POST JSON;留空关闭

// ComposeStack
{ "project_name": string,
  "services": [ { "service": string, "image": string|null, "has_build": bool,
                  "mode": "Local"|"Pull",
                  "match_state": "Exact"|"RepoOnly"|"Missing",
                  "local_tag": string|null,          // RepoOnly 时=本地实际 tag
                  "warning": string|null,            // 含默认命名命中/未命中、私有仓库提示等
                  "registry": string|null } ],       // serde default;docker.io 豁免为 null
  "errors": string[],                                // 非空=阻断部署
  "overrides": string[] }                            // serde default;检测到的 override 文件名

// StackPreview(preview_stack_changes 返回)
{ "entries": [ { "service": string, "image": string, "mode": "Local"|"Pull",
                "action": "Recreate"|"Create"|"Unchanged"|"Pull"|"Absent" } ],
  "errors": string[] }

// DeployRecord(get_history 元素)
{ "ts": string, "mode": "single"|"stack", "server_name": string, "project_name": string,
  "images": string[], "success": bool, "message": string, "duration_secs": number }
```

## 4. 全局错误约定

- 所有命令 `Result<T, String>`,错误信息**中文带上下文**
- Promise reject 的字符串直接 toast/错误框展示,不再加工
- 取消统一文案 `"部署已取消"`;SSH 超时 `"连接超时(15 秒):…"` / 命令超时按常量名区分
- `deploy-done` 失败 message 为中文错误(含失败环节上下文);日志另有 `部署失败: <原因>` 行

## 5. 变更流程清单(改契约时)

1. 改 Rust struct/命令 → `cargo test` 全绿
2. 改对应 JS 调用与字段读取 → `node --check` + id 引用核对
3. 更新本文档对应表格
4. 跑 `npm run tauri build` 冒烟 + 至少一次真实页面操作
