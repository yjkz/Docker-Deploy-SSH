# 07 — 安全与已知取舍

## 敏感数据数据流(SSH 密码 / 私钥口令 / SMTP 密码,已审计闭环无泄漏)

```
前端密码框(type=password)
  → invoke('encrypt_password', {plain})      # SSH 密码唯一一次明文过 IPC
  → Rust: windows-dpapi encrypt(CurrentUser) → base64
  → servers.json 的 auth.password_enc(密文落盘)
运行期:
  前端始终传 password_plain: null(或临时输入)
  → 后端 resolve_password:dpapi_unprotect(password_enc) → 内存瞬时明文 → SSH 认证

私钥口令(阶段三,key_pass_enc):服务器表单输入(不回显)
  → 「记住口令」勾选:连接成功后 DPAPI 加密存 auth.key_pass_enc;不勾=仅本次连接使用,不落盘
  → 运行期 resolve_key_passphrase:dpapi_unprotect(key_pass_enc) → SshClient::connect 透传
    load_secret_key(key_path, passphrase);口令错误 → 中文映射「私钥口令错误或私钥已损坏」

SMTP 密码(阶段二,notify.json 的 email.password_enc):通知中心表单输入
  → notify_save_config:非空明文 → dpapi_protect 落盘;留空 → 保留已存密文
  → 查询脱敏:notify_get_config 只回 passwordSaved 布尔值,明文/密文都不出后端
  → 发送时 resolve_email_password 解密(内存瞬时);发信经 lettre(内存拼接,不落日志)

不变量:
  - 不存在解密命令;dpapi_unprotect 仅在 resolve_password / resolve_key_passphrase /
    config_io(导出解密→导入重加密)/ notify(SMTP 密码)内部调用
  - 明文/密文不进日志、不进事件、不进 localStorage、不进错误信息
  - DPAPI CurrentUser 作用域:同机同用户才可解;直接拷贝 config/ 到其他机器后密码必须重录
    (跨机器迁移用「配置中心」导出/导入:blob 内为口令加密的明文,导入时本机重新 DPAPI 加密)
```

## 配置导出加密格式(阶段三,config_io.rs)

```
文件 = JSON 信封 {"version":1, "kdf":"argon2id", "salt_b64", "nonce_b64", "data_b64"}
密钥  = Argon2id(导出口令, salt 16B 随机;Params::default: m=19MiB, t=2, p=1)→ 32 字节
data  = AES-256-GCM(认证加密,nonce 12B 随机)的明文 JSON:
        {"servers":[...], "projects":[...], "notify":{...}}
        blob 内 SSH 密码/私钥口令/SMTP 密码为明文(可移植),靠信封加密保护
导入口令错误 / 文件被篡改 → GCM 标签校验失败,统一报「导出口令错误或文件已损坏」(二者不可区分,有意为之)
导出口令不入文件;丢失口令 = 数据不可恢复(无后门)
```

## 主机密钥:TOFU 校验(阶段三实现,原「无条件接受」安全债已清)

`ssh.rs` 的 `ClientHandler::check_server_key` 按 per-server 指纹校验(UPGRADE-PLAN 风险声明修改点 1):

- **指纹口径**:OpenSSH 风格 `SHA256:` + base64(nopad)(SHA-256(公钥 SSH wire blob)),与 `ssh-keygen -lf` 一致(russh 的 `PublicKey::fingerprint` 补前缀)
- **首次连接**(配置 `host_key_sha256` 为 None):接受并把观察到的指纹交由命令层 `persist_host_key_if_needed` 落盘(TOFU 信任-on-first-use;连接失败路径不落盘)
- **已有记录且匹配** → 接受
- **不匹配** → 拒绝连接,固定文案:「服务器主机密钥已变更!可能为服务器重装/换 IP,也可能存在中间人风险。如确认无误,请在服务器管理中重新信任该主机。」
- **重置**:03 服务器管理每服务器展示当前指纹(等宽)+「重新信任」按钮 → `retrust_host_key` 清空记录(二次确认),下次连接重新 TOFU
- 部署主线与远程管理全部建连路径(commands.rs 与 manage.rs 的 `connect_server`)统一接入;指纹记录随配置中心导出/导入迁移
