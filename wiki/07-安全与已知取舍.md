# 07 — 安全与已知取舍

## 密码数据流(已审计,闭环无泄漏)

```
前端密码框(type=password)
  → invoke('encrypt_password', {plain})      # 唯一一次明文过 IPC
  → Rust: windows-dpapi encrypt(CurrentUser) → base64
  → servers.json 的 auth.password_enc(密文落盘)
运行期:
  前端始终传 password_plain: null(或临时输入)
  → 后端 resolve_password:dpapi_unprotect(password_enc) → 内存瞬时明文 → SSH 认证
不变量:
  - 不存在解密命令;dpapi_unprotect 仅在 resolve_password 内部调用
  - 明文/密文不进日志、不进事件、不进 localStorage、不进错误信息
  - DPAPI CurrentUser 作用域:同机同用户才可解;拷贝配置到其他机器后密码必须重录
```

## 注入防护

| 面 | 防护 |
|---|---|
| 本机 Docker CLI | `Command::new("docker").args([...])` 参数数组,不经 shell;镜像名/tag 不拼字符串 |
| SSH 远端命令 | 全部经 `shell_single_quote`(单引号包裹 + `'\''` 转义)后才拼进命令;`remote_dir`/`compose_file`/服务名/路径均覆盖;cleanup 的 glob 刻意留在引号外(否则不展开),引号内前缀已转义——有防注入单测 |
| 文件映射路径 | `remote_join`:rel 以 `/` 开头不逃逸(仍相对 remote_dir 拼接);**不防 `..` 相对逃逸**(见下方取舍);本地路径不存在时报错含路径 |
| compose 解析 | serde_yaml 结构化解析,不 eval;重复键 YAML 直接解析失败(安全侧) |
| 前端 DOM | 全部 `createElement`/`textContent`,禁 innerHTML 拼数据(镜像名/服务器名按不可信输入处理) |
| 子进程窗口 | Windows 下统一 `CREATE_NO_WINDOW`(GUI 进程防闪黑框) |

## 主机密钥:无条件接受(已知安全债,首位)

`ssh.rs` 的 `check_server_key` 直接 `Ok(true)`:每次连接接受任意主机密钥,连 TOFU(首次记录后续比对)都没有。威胁:中间人可截获密码认证明文、篡改 `docker load`/`compose up` 指令。代码有注释声明是有意取舍(个人工具、内网场景)。**合并后安全债第一位:实现 known_hosts 记录 + 变更告警。**

## 设计决策记录(裁决史,改相关代码前先读)

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| 1 | 配置存应用目录(便携),`DD_CONFIG_DIR` 语义=应用目录(内部拼 `config/`) | 免安装污染;测试注入 | 装进 Program Files 等只读目录会配置失败(错误清晰) |
| 2 | Docker 走 CLI 子进程,不直连 Engine API | Windows named pipe 处理简单;CLI 语义稳定 | 每次调用 spawn 进程(check_host 一次 4 个;有 CREATE_NO_WINDOW) |
| 3 | gzip 用 flate2 库流式,不依赖系统 gzip | Windows 无自带 gzip | 无 |
| 4 | size_bytes 按 1024 进制换算 | 简单一致 | docker 实际 SI 千进制,显示有少量偏差 |
| 5 | DPAPI 依赖 windows-dpapi 0.1(小版本 crate) | 源码核实 Scope::User 正确 | 不宜盲目升级(0.2 签名变) |
| 6 | russh 0.46 + russh-sftp 2.4(计划书写 0.45) | 0.45 缺所需 API | 锁定版本 |
| 7 | 服务器管理页不受宿主环境闸门锁定 | 配置编辑不依赖 Docker;仅部署动作受闸门 | 无 |
| 8 | 仅 image 无 build 的服务默认 Pull(即使本地 Exact 匹配) | 公共镜像本地通常也有,误判面更小;分类表一键可切 | 手动 build 的用户需点一次切换 |
| 9 | Missing+has_build(写了 image 未 build)不加警告 | 属正常工作流("还没 build");✗ 徽章已提示;部署期 save 报错兜底 | 极少量噪音换不误报 |
| 10 | serde_yaml 0.9 + 显式 `apply_merge()` | 0.9 不自动应用 `<<` 合并键(曾致锚点 compose 误解析,已修+fixture) | 0.9 已 archived,关注社区续作 |
| 11 | compose 副本上传为远端 `docker-compose.yml` | `-f` 需要远端文件;本地副本路径在服务器无效 | 覆盖远端同名文件(项目目录语义内) |
| 12 | releases 留档保留 5 份,时间戳到秒 | 免手动回滚基础 | 同秒并发混包(单用户可接受);磁盘占用 |
| 13 | 日志文件 target 全构建启用;Stdout 仅 debug | release GUI 进程无 stdout,fern 写入会 panic(复审抓出的回归) | release 排障只能看文件 |
| 14 | 全局单取消标志;前端部署中禁重复发起 | 简单;单窗口场景够用 | 后端层并发 deploy 会互相冲掉取消(前端已防) |
| 15 | 单镜像勾选日期标签时,服务器 load 后追加 `docker tag <日期tag> <原引用>` | 让 compose 引用的原 tag 同步指向新镜像,变更检测生效(否则容器静默不更新);日期 tag 保留作版本档案 | 服务器上历史日期 tag 随部署次数累积(可 `docker image prune` 外的按需清理;悬空旧层由 prune 处理) |
| 16 | 健康检查 `compose ps --all` + ExitCode 语义(exited≠0→失败;=0→继续观察;字段缺失→保守判失败) | 默认 ps 只列 running,"启动即退出"的服务会被健康服务掩盖而误判通过 | exit-0 一次性初始化服务会误报,报错文案已提示关闭健康检查 |
| 17 | 镜像包上传失败后同路径重试一次(2s 退避) | 激活 SFTP 断点续传(否则每次部署新时间戳/uuid,续传永远不可达) | 非瞬态失败也会多试一次(≤2s+1 次) |
| 18 | webhook URL 日志脱敏(只记 host;ureq 错误只记状态码/Kind) | webhook URL 常内嵌 token,全量落日志有凭据泄露面 | 诊断信息略少(Transport source 被舍弃) |
| 19 | 默认镜像名兜底扫描:候选=顶层 name: → origin.json 原始目录名 → 父目录名;docker.io 豁免私有仓库提示 | build 无 image 是高频场景;origin.json 解决副本路径目录名失真;docker.io 显式前缀误报登录提示属噪音 | exit-0/非常规命名(container_name、build.tags)不在覆盖范围 |
| 20 | 全表单失败走强化通道(formFailLoud:内联+滚动 60ms 延迟+toast),缺项聚合提示 | 错误框在长表单顶部而视口在底部 = "点了没反应";点击按钮的原生焦点滚动会覆盖同步滚动,故延迟一拍 | 无 |
| 21 | 项目配置新增 health_wait_secs / pre_deploy_cmd / post_deploy_cmd / notify_webhook(全 serde default) | 生产底线:备份钩子、部署结果如实上报 | 旧配置缺字段自动兼容 |

## 已知限制 / 合并后待办(按优先级)

1. **host key TOFU**(安全债首位)
2. 部署向导未强制重跑宿主机检测(依赖 check 页状态 + localStorage 恢复的短暂解锁窗口;后端失败安全)
3. `image_filter` 配置字段暂未被消费(项目下拉不过滤镜像)
4. BusyBox/Alpine 服务器 `df -PBG` 拿不到磁盘数据(预检告警跳过;主流 Debian/Ubuntu 无碍)
5. SFTP 上传中取消不生效(步骤边界生效);~~断点续传~~ **已实现**(v0.4.0,失败后同路径重试触发)
6. compose 的 `${VAR}` 插值仅支持同目录 `.env`(不支持 `--env-file` 多文件/shell 环境)
7. import_compose 写配置失败时残留空 `stacks/<uuid>/` 目录(无功能影响)
8. 后端日志的 `log::warn!` 在 release 只落文件不外显(设计如此)
9. 部署历史:并发部署结束时理论丢一条;panic 路径不记录(单用户桌面场景可接受)
10. 部署预览按 remote_dir 基名过滤容器:compose 顶层 `name:` / 路径含大写等规范化场景会 miss(保守判 Create,不影响部署正确性)
11. 健康检查对 exit-0 一次性初始化服务会误报(报错文案已提示关闭健康检查)
12. 表格行 hover 反白时 badge-info 文字不可见(系统既有样式债,建议加 hover 豁免)
