# 06 — 部署流程与回滚

两条管线的逐步语义。实现集中在 `commands.rs` 的 `run_deploy`(单镜像)/ `run_deploy_stack`(整栈);共同骨架在 `spawn_deploy_task`。

## 共同骨架

```
命令同步返回 Ok ──▶ tauri::async_runtime::spawn ──▶ CatchPanic 包裹(panic→deploy-done failure)
                                                     任何路径 deploy-done 恰好一次
取消:DeployState.cancelled(AtomicBool);开始时重置;步骤边界/打包上传循环逐项/
     exec 输出行回调/末尾复查处检查 → Err("部署已取消")
密码:resolve_password(Key→None;Password→password_plain 优先,否则 DPAPI 解密 password_enc)
中止:任一步失败 → 停止后续步骤,emit deploy-done{success:false,message:中文错误}
```

## 单镜像管线(deploy,5 步)

| 步 | 动作 | 细节 |
|---|---|---|
| 1 打标签 | `use_date_tag=true` 时:`make_deploy_tag` 生成 `repo:YYYYmmdd-HHMMSS`;本地已存在同名 tag → sleep 1s 重生成,最多 5 次;`tag_image`。false 时沿用原 tag | 日期 tag 是"版本档案";回滚能力的来源 |
| 2 导出压缩 | `image_size` 预检:临时目录盘剩余 ≥ 镜像×1.5;`save_gzip` → `temp_dir/<uuid>.tar.gz`(TempFileGuard 守卫);进度按 5MB 节流发日志。**导出的是日期 tag 那份**(勾选时) | |
| 3 上传镜像 | SSH 建连 → `sftp_upload` 到远端 `/tmp/`(进度按 10% 发日志);随后 `sync_files` 同步项目 fileMappings(compose/.env/SQL 等到 remote_dir) | |
| 4 装载 | `docker load -i '/tmp/<file>'`(600s,输出转发);**勾选日期标签时追加 `docker tag <日期tag> <原引用>`**(60s)——把 compose 引用的原 tag(来自 `req.image`)也指向新镜像,否则 compose 变更检测失效、容器不重建。旧镜像变悬空,历史日期 tag 留在服务器上成为按版本回滚点 | |
| 5 启动 | `cd '<remote_dir>' && docker compose -f '<compose_file>' up -d`(600s) | |
| 收尾 | 删远端 /tmp tar;本地 tar 由 Drop 守卫删 | |

## 整栈管线(deploy_stack,6 步)

前置(步骤 1 内):services 非空;Local 类 image 非空;project/server 存在;compose 副本存在。

| 步 | 动作 | 细节 |
|---|---|---|
| 1 分类确认 | 校验+进度起点 | 分类来自前端确认后的 services(用户可改,可"保存为默认") |
| 2 打包 | Local 类逐个 `image_size` 求和 ×1.5 磁盘预检;逐个 save_gzip | 大小取不到(镜像不存在)→ 跳过预检,save 阶段报错 |
| 3 上传 | 远端建 `<remote_dir>/releases/<yyyymmdd-HHMMSS>/`;compose 副本上传为远端 `docker-compose.yml`(+.env);逐包 sftp 上传到 releases 目录;sync_files 传文件映射 | **tar 不进 /tmp,直接进 releases——留档即回滚点** |
| 4 装载 | 逐包 `docker load -i '<releases>/<包>'`(600s) | |
| 5 拉取 | Pull 类非空:`cd '<remote_dir>' && docker compose -f docker-compose.yml pull <services...>`(900s);失败→报错提示"检查服务器能否出网,或把这些服务改为本地传输"。Pull 空→跳过 | |
| 6 启动 | `cd '<remote_dir>' && docker compose -f docker-compose.yml up -d`(900s) | |
| 收尾 | releases 只保留最新 5 份(`ls -1dt … | tail -n +6 | xargs -r rm -rf`,失败仅告警);本地 tar 全删 | |

## 回滚操作(手动,服务器上)

**单镜像模式(勾选日期标签部署过)**:每次部署都会在服务器上留下一个带日期 tag 的版本镜像(load 后 retag,日期 tag 保留),直接切换指针即可:

```bash
# 1. 看服务器上有哪些历史版本
docker images | grep myapp
# 2. 把 latest 指回旧版本(指针移动,零拷贝)
docker tag myapp:20260829-143000 myapp:latest
# 3. 重建容器
cd /opt/<你的项目> && docker compose -f docker-compose.yml up -d
```

**整栈模式**:依赖 releases 留档(每次部署的镜像包保留最近 5 份):

```bash
# 1. 看有哪些回滚点
ls -1dt /opt/<你的项目>/releases/*/
# 2. 把想要的旧镜像包装载回去(覆盖同名 tag)
docker load -i /opt/<你的项目>/releases/<时间戳>/<包名>.tar.gz
# 3. 重启栈
cd /opt/<你的项目> && docker compose -f docker-compose.yml up -d
```

若需更强回滚(按版本切 compose),属于未来增强。

## 环境检测闸门规则

| 层 | 未通过的后果 | 入口 |
|---|---|---|
| 宿主机 | `AppState.hostOk=false` → 镜像列表/部署向导导航灰置不可进;服务器管理页可进(黄条提示)但部署动作会被后端再拦 | `host_check` / 检测页 |
| 服务器 | 部署向导开始部署前强制 `server_env_check`,任一项未通过 → 阻断 + 跳转按钮 | `test_server` / 服务器页 |
| 部署中 | 后端仍会再验(打包磁盘 ×1.5、Local 镜像存在性等) | 双保险,前端非唯一防线 |

## 已知的时序/边界行为

- 取消是协作式:导出/SFTP 大文件传输中不中断,在步骤边界或 exec 输出行时生效 → UI 有"将在当前步骤结束后生效"提示
- `deploy-done` 成功与"最后一步后瞬间取消"存在极小竞态窗口(与单镜像管线一致,已知可接受)
- Local 类镜像本地不存在:预检阶段(打包)由 `docker save` 报错;更早的拦截靠前端匹配徽章(✗ 本地不存在)
- releases 时间戳精确到秒:同秒内并发两次整栈部署会同目录混包(单用户桌面场景,可接受)

## compose 默认镜像名兜底扫描(v0.4.3 起)

服务有 `build:` 但未写 `image:` 字段时(compose v2 会把构建产物命名为 `<项目目录名>-<服务名>`),解析阶段自动按以下候选扫描本地镜像并回填:

1. compose 顶层 `name:`(若写)
2. **原始 compose 目录名**——导入时记录在副本目录的 `origin.json`,不受副本迁移影响
3. 副本/原始路径的父目录名(最后手段)

- 命中:镜像自动填入(多 tag 优先 `latest`),匹配状态=精确匹配,warning 提示"建议在 compose 中显式写 image: 固化命名"
- 未命中:保持"本地不存在",warning 列出已扫描的候选名(uuid 形态的内部目录名不展示)
- 纯函数与副本结构(uuid 目录 + origin.json)均有单测覆盖
